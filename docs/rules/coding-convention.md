# 코딩 컨벤션

Keeply의 컨벤션을 참고하되 Ttak의 언어와 현재 구현에 맞춘다.
이 문서는 공통 원칙과 적용 경로의 기준이다. 구체적인 구문·이름·상태 규칙은 언어별 문서에 둔다.

## 적용 범위

| 대상 | 적용 규칙 |
| --- | --- |
| `apps/macos`의 Swift·SwiftUI | [Swift 코딩 컨벤션](swift-coding-convention.md) |
| `apps/web`의 React·TypeScript | [웹 코딩 컨벤션](web-coding-convention.md) |
| 저장소 공통 JavaScript 도구 | 기존 Node ESM 구조·파일 내부 스타일과 공통 원칙. React 컴포넌트 규칙은 적용하지 않음 |
| 브랜치·커밋·PR·라벨 | [Git 컨벤션](git-convention.md) |
| 제품 경계·권한·실기기 검증 | [macOS 개발 기준](macos-development.md) |

한 언어의 규칙을 다른 언어에 그대로 적용하지 않는다. 특히 JavaScript의 var 금지와
Swift의 var, React의 컴포넌트·훅과 SwiftUI의 View·상태는 구분한다.

## 공통 원칙

- 사용 지점에서 의도가 드러나는 이름을 사용한다. 의미 없는 축약이나 `data`, `temp`만으로 역할을 감추지 않는다.
- 변경할 필요 없는 값은 해당 언어의 불변 선언을 우선하고, 실제 상태 변경에는 가변 선언을 사용한다.
- 값·상태·부작용의 소유 위치를 명확히 한다. 중복 상태를 만들어 두 곳에서 갱신하지 않는다.
- 도메인 로직은 해당 기능에 둔다. 두 번 사용됐다는 이유만으로 무조건 `utils`나 공용 계층을 만들지 않는다.
- 기존 코드에서 해결 가능한 단순 작업에 새 패턴·추상화·라이브러리를 강제하지 않는다.
- 수정·제외·정렬되는 목록은 항목의 안정적인 식별자를 사용한다. 위치를 항목 정체성으로 취급하지 않는다.
- 오류·권한·취소·부분 성공을 정상 결과로 숨기지 않는다. 합의되지 않은 제품 동작을 스타일 규칙으로 확정하지 않는다.
- 비밀 값과 개인 일정 원문을 디버그 로그·공유 명세·Git에 남기지 않는다. 검증 예시는 합성 데이터를 사용한다.
- 설명이 필요한 공개 계약·비직관적인 제한은 이유를 문서화한다. 코드 내용을 반복하는 주석은 늘리지 않는다.
- 수정한 부분은 그 파일의 기존 스타일을 따른다. 무관한 파일의 일괄 재포맷은 별도 요청 없이는 하지 않는다.

## 형식과 자동화

[.editorconfig](../../.editorconfig)의 Swift 4칸·그 외 기본 2칸, UTF-8·LF를 따른다.
웹의 세부 구문은 현재 코드 스타일을 기준으로 한다. 이 규칙은 SwiftFormat/SwiftLint/Prettier 설치나
CI 강제를 뜻하지 않는다. 실행 가능한 기존 검사와 수동 확인 범위는 [작업 흐름](ai-workflow.md)을 따른다.
새 도구를 추가할 때는 그 도구가 문서와 충돌하지 않도록 별도로 구성한다.

# 작업 명세: 코드 포맷 자동화 세팅

## 연결 정보

- 이슈: #9 / https://github.com/ttak-app/ttak-workspace/issues/9
- 브랜치: feat/code-formatting/#9
- specRevision: 1

## 목적

React 웹과 Swift 앱에 각각 맞는 포맷터를 설정해 기존 코드 형식을 일관되게 유지한다.
코드를 수정하는 명령과 읽기 전용 검사 명령을 구분하고, 기존 CI에서 변경된 대상만 검사한다.

## 작업 범위

### 포함

- apps/web에 정확한 버전의 Prettier 개발 의존성 및 웹 범위의 설정과 생성물 제외 규칙 추가.
- apps/macos에 Swift 툴체인의 swift-format 설정 추가.
- 각 대상의 수정 및 검사 명령, CI 연결과 기존 경로 분류 회귀 검증.
- 대상 앱 코드의 초기 포맷 적용과 기존 규칙 및 실행 안내 갱신.

### 제외

- 커밋, push, PR 생성과 merge 및 원격 보호 규칙 변경.
- 서버, Git 훅, 새 린터, 에디터 확장 설치 및 새로운 코딩 컨벤션 추가.
- 저장소 전체 문서, 하네스 실행 도구, Xcode 프로젝트 파일과 앱 동작의 무관한 수정.

## 설계 결정

- 웹은 Prettier 3.9.10을 apps/web의 devDependencies에 고정하고 npm 루트 잠금 파일로 재현한다.
- 웹 설정은 앱 폴더 안에 두며 2칸 들여쓰기, 작은따옴표, JSX 큰따옴표와 세미콜론 생략을 유지한다. 기타 줄바꿈은 도구 기본값을 사용한다.
- 웹 포맷 범위는 앱 폴더의 JS, MJS, CJS, TS, TSX, CSS, JSON과 HTML이다. Markdown 및 루트 Node 도구에는 적용하지 않는다. 생성물과 설치 의존성은 제외한다.
- Swift는 xcrun swift format을 사용하고 .swift-format에서 4칸 들여쓰기를 지정한다. Ttak과 TtakTests 폴더의 Swift 파일에만 적용한다.
- Swift 포맷터는 선택된 Xcode 툴체인을 따른다. CI의 기존 Xcode 26.6 선택을 유지하고 로컬과 도구 버전 차이 가능성을 문서화한다.
- npm run format:web 및 format:macos는 파일을 수정한다. format:check:web과 format:check:macos는 파일을 수정하지 않고 위반 시 실패한다.
- CI의 Web에는 웹 포맷 검사, macOS Build에는 Swift 포맷 검사만 추가한다. 기존 Changes와 CI Result 및 기본 PR 이벤트는 유지한다.
- 포맷 설정 파일은 각 앱 폴더 아래 있으므로 기존 분류에서 해당 앱만 선택한다. 루트 명령 및 CI 정의 변경은 기존 정책대로 전체 검사를 선택한다.
- 상태와 사용자 데이터 흐름 변경은 없어 N/A다. 포맷 검사는 앱 동작 검증이나 린트를 대체하지 않는다.

## 완료 조건

- AC-1: 웹 포맷터 버전과 설정이 고정되고 기존 웹 코드 규칙을 유지하며 웹 폴더에만 적용된다.
- AC-2: Swift 포맷터는 4칸 들여쓰기로 앱과 테스트의 Swift 소스만 처리한다.
- AC-3: 두 대상의 수정 및 읽기 전용 검사 명령이 정상 실행되고 위반한 파일은 검사 실패, 수정 후 성공한다. 검사는 원본을 수정하지 않는다.
- AC-4: CI는 변경 감지에 따라 해당 앱 job에서 포맷 검사만 실행하고 의도된 생략과 실패가 기존 최종 판정에 반영된다.
- AC-5: 초기 포맷 적용 뒤 웹 lint, 타입 검사와 빌드, Swift unsigned 빌드 및 필요한 CI와 하네스 검사가 통과하거나 실제 제약을 보고한다.
- AC-6: 문서와 명령, 적용 범위 및 실제 검증 결과가 일치하며 새 Git 훅이나 린터 및 무관한 정책을 추가하지 않는다.

## 검증 방법

| 완료 조건 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| AC-1, AC-2 | 설정과 잠금 파일 및 포맷 결과 검토 | 기존 언어별 규칙 유지, 수정 범위 제한 |
| AC-3 | 두 format:check 명령 및 임시 위반 파일의 검사, 수정과 재검사 | 정상 성공, 위반 실패, 검사 중 원본 보존 |
| AC-4 | CI 경로 및 연결 테스트와 actionlint | 웹 설정은 웹만, Swift 설정은 Swift만 선택. 각 job에 검사 연결 |
| AC-5 | lint:web, check-types:web, build:web, macos:build 및 CI 도구와 하네스 구조 검사 | 실제 종료 코드와 한계 기록 |
| AC-6 | 문서 링크, 명령과 전체 diff 수동 검토 | 일관된 안내, 무관한 변경 없음 |

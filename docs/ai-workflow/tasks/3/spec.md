# 작업 명세: CI 세팅

## 연결 정보

- 이슈: #3 / https://github.com/ttak-app/ttak-workspace/issues/3
- 브랜치: chore/ci-setting/#3
- specRevision: 2

## 목적

Swift macOS 앱과 React 랜딩 페이지를 서로 독립된 검증 대상으로 관리한다.
PR의 변경 파일과 실제 실행 의존성을 확인해 필요한 검사만 실행하고,
관련 없는 앱의 빌드, 의존성 설치와 테스트에 리소스를 사용하지 않는다.
이후 랜딩 페이지 CD도 변경된 대상만 배포하도록 연결할 수 있게 설계한다.

## 현재 상태와 이번 요청

- revision 1의 CI는 모든 PR에서 Harness, Web, macOS Build를 실행하도록 구현되어 있다.
- 사용자는 앱과 웹의 불필요한 동시 검증을 지적하고 변경 감지 기반 설계안을 선택했다.
- 이번 요청은 이 명세를 발전시키는 작업이다. CI 워크플로, 운영 문서, 원격 GitHub 설정은 수정하지 않는다.
- 아래 완료 조건은 revision 2의 후속 구현 기준이며, 기존 구현과 검증 결과만으로 충족했다고 판단하지 않는다.

## 작업 범위

### 포함

- `.github/workflows/ci.yml`에서 변경 감지, 대상별 조건부 검사, 최종 결과 취합을 구성하는 설계.
- main, develop 대상 PR의 전체 변경을 기준으로 앱, 웹, 하네스의 검사 대상을 결정.
- 앱과 웹이 각각 변경된 경우 해당 검사만 실행하고, 둘 다 변경되면 병렬 실행.
- 하네스의 구조 검사와 도구 회귀 테스트를 구분해 문서 변경에 불필요한 회귀 테스트 생략.
- 공통 파일의 실제 사용 범위에 따른 영향 분류와 삭제, 이동, 감지 실패 처리.
- 단일 필수 검사 `CI Result`의 성공, 실패와 의도된 생략 판정 기준.
- 변경별 검증 시나리오, 후속 원격 실행 확인과 필수 검사 연결 계획.

### 제외

- 이번 요청에서 CI 구현 파일과 다른 공유 문서를 수정하거나 구현 에이전트를 다시 실행하는 작업.
- 커밋, push, PR 생성, merge와 원격 ruleset 변경.
- 랜딩 페이지 호스팅 선정과 CD 구현, 앱 서명, 공증과 배포.
- Swift 테스트 타깃 신설, 새 코딩 컨벤션 도구, 자동 라벨링과 추가 브랜치 정책.
- 앱 기능, 하네스 엔진, 앱 의존성 및 잠금 파일의 무관한 변경.
- 변경 감지를 위해 Turborepo나 Nx 등 별도 모노레포 프레임워크 도입.

## 설계 결정

### 처리 흐름과 책임

1. `Changes`: 가벼운 Ubuntu 작업에서 PR 전체 변경을 수집하고 검사 대상 플래그를 출력한다.
2. `macOS Build`, `Web`, `Harness`: 각 플래그에 따라 필요한 작업만 실행한다. 필요한 작업끼리는 병렬 실행한다.
3. `CI Result`: 감지 결과와 각 작업의 실제 종료 상태를 대조해 최종 병합 판정 결과를 만든다.

CI 정의는 기존 `ci.yml` 하나 안에 둔다. 앱과 웹 사이에 코드 의존성이 있다고 가정하지 않는다.
일반 PR에서는 변경 감지와 결과 취합만 항상 실행하며, 생략 대상 작업에는 runner를 할당하지 않는다.
특히 웹만 변경한 PR에서 macOS runner를 시작하거나 Xcode를 실행하지 않는다.
문서만 변경한 PR에서 웹 의존성 설치와 앱 빌드를 수행하지 않는다.

### 변경 감지

- PR의 마지막 커밋 하나가 아니라 대상 브랜치와 비교한 PR 전체 변경을 판별한다.
- PR 생성, 재개, 추가 커밋과 리뷰 준비 상태 전환 시 감지를 다시 수행한다.
- 파일 추가, 수정, 삭제를 포함한다. 이동과 이름 변경은 이전 경로와 새 경로의 영향을 함께 확인한다.
- 감지 수단은 `dorny/paths-filter` 같은 전용 Action을 우선 검토한다. 도입 시 입력, 권한, 삭제와 이동 처리 및 목록 수집 한계를 확인하고 검증한 커밋 SHA로 고정한다.
- PR API 방식이면 변경 감지 작업에만 필요한 `pull-requests: read`를 부여한다. 다른 작업은 기존 `contents: read`를 유지한다.
- 경로 분류는 검토 가능한 한 곳에 두고, 폴더명이 비슷하거나 루트 파일이라는 이유로 전체 검사를 선택하지 않는다.
- 파일 목록을 얻지 못하거나 불완전하게 수집한 경우에는 '변경 없음'으로 처리하지 않는다. 변경 감지 실패와 최종 결과 실패로 드러낸다.

### 변경 영향표

여러 범위가 변경되면 필요한 검사의 합집합을 실행한다.
일반 설명 문서와 `.gitkeep`을 앱 코드 패턴에서 구분하고,
앱 폴더의 `AGENTS.md`처럼 하네스 검사 대상인 문서가 앱 빌드를 함께 선택하지 않도록 한다.

| 변경 경로 또는 내용 | macOS 빌드 | 웹 검사 | 하네스 구조 검사 | 하네스 도구 테스트 |
| --- | --- | --- | --- | --- |
| `apps/macos`의 Swift, Xcode 프로젝트, 스킴, 리소스와 권한 설정 | 실행 | 생략 | 생략 | 생략 |
| `apps/web`의 소스, 리소스, package 및 빌드와 린트 설정 | 생략 | 실행 | 생략 | 생략 |
| 루트 `package-lock.json` | 생략 | 실행 | 생략 | 생략 |
| `tools/macos`의 실행 도구와 테스트 | 실행 | 생략 | 실행 | 실행 |
| `tools/ai-workflow`, `tools/branch-review`의 실행 도구와 테스트 | 생략 | 생략 | 실행 | 실행 |
| `AGENTS.md`, 앱별 `AGENTS.md`, `.agents`, `docs/rules`, 하네스 명세와 연결 문서 | 생략 | 생략 | 실행 | 생략 |
| 일반 README, 설명 문서와 `.gitkeep`만 변경 | 생략 | 생략 | 검사 대상 문서와 링크에 영향이 있을 때만 실행 | 생략 |
| 루트 `package.json` | 실행 | 실행 | 실행 | 실행 |
| `.nvmrc` | 실행 | 실행 | 실행 | 실행 |
| `.github/workflows/ci.yml` 및 변경 감지 분류 정의 | 실행 | 실행 | 실행 | 실행 |

- 루트 잠금 파일은 현재 웹 의존성만 관리하므로 Swift 빌드를 선택하지 않는다.
- 루트 `package.json`은 현재 모든 검증 진입 명령과 npm 실행 환경을 정의하고, `.nvmrc`는 모든 작업에서 사용한다. 이 두 파일은 현재 구조에서 공통 검사 대상으로 분류한다.
- CI와 감지 정의 변경은 작업 선택 자체를 바꾸므로 전체 경로의 연결을 검증한다.
- 새 공용 패키지나 실행 설정을 도입하면 실제 소비 대상을 확인해 영향표와 검증 사례를 함께 갱신한다. 현재 없는 앱 간 의존성을 미리 추가하지 않는다.

### 대상별 실행

- `Web`: 기존 Ubuntu 환경에서 `npm ci` 후 `lint:web`, `check-types:web`, `build:web`를 실행한다. 선택되지 않으면 설치부터 생략한다.
- `macOS Build`: 기존 macOS 26, Xcode 26.6 환경에서 `npm run macos:build`로 서명 없는 Debug 빌드를 수행한다. 선택되지 않으면 작업 전체를 생략한다.
- `Harness`: 구조 검사와 도구 테스트의 선택 결과를 별도 플래그로 관리한다. 구조만 바뀌면 `workflow:harness-check`만 실행하고 도구 회귀 테스트는 생략한다. 도구가 바뀌면 필요한 구조 검사와 기존 `workflow:test`를 실행한다.
- 하네스와 macOS 실행 도구는 Node 기본 모듈을 사용하므로 웹 의존성을 설치하지 않는다.
- Node 24, npm 11.3.0, 공식 Actions SHA 고정, 웹 npm 다운로드 캐시, PR별 이전 실행 취소와 시간 제한은 기존 구성을 유지한다.
- 현재 Swift 테스트 타깃이 없으므로 `macos:test`는 추가하지 않는다. 하네스 도구 테스트 통과를 Swift 앱 테스트 통과로 표현하지 않는다.

### 최종 결과와 병합 조건

워크플로 전체를 경로 필터로 생략하지 않고, 내부 검사 작업에 조건을 적용한다.
`CI Result`는 감지와 검사 작업들에 의존하며 선행 작업의 실패나 생략에도 실행되도록 구성한다.
필수 상태 검사는 개별 작업 세 개에서 `CI Result` 하나로 연결하는 방식으로 변경한다.

| 관측 결과 | `CI Result` 판정 |
| --- | --- |
| 변경 감지 성공, 선택한 모든 검사가 성공 | 성공 |
| 변경 감지 성공, 선택하지 않은 검사가 의도대로 생략 | 성공 |
| 일반 문서 변경으로 무거운 검사가 모두 불필요 | 감지와 대상 분류를 확인한 후 성공 |
| 선택한 검사 실패 또는 취소 | 실패 |
| 선택한 검사가 예상과 달리 생략되거나 필수 출력 누락 | 실패 |
| 변경 감지 실패, 취소 또는 결과 불명확 | 실패 |

항상 실행되는 결과 취합 작업은 설치나 빌드를 반복하지 않고 상태만 확인한다.
`continue-on-error`나 모든 skipped 상태의 무조건 성공 처리로 실제 실패를 숨기지 않는다.
PR 요약에 변경으로 선택한 검사와 생략 이유를 남겨 실행 범위를 확인할 수 있게 한다.

### 후속 CD 연결

현재 작업에서는 CD를 구현하지 않는다.
후속 웹 CD는 main에 실제 반영된 변경을 기준으로 배포 대상을 판별하고,
웹에 영향이 있는 경우에만 필요한 검증 성공을 확인한 뒤 배포한다.
PR 실행의 임시 플래그를 main의 배포 실행에서 그대로 사용할 수 있다고 가정하지 않는다.
Swift만 변경됐다면 랜딩 페이지를 배포하지 않는다.

### 구현과 원격 확인 단계

- 이번에는 명세만 갱신한다. 현재 CI 구현과 운영 문서는 revision 1 상태임을 유지해 구분한다.
- 후속 구현 시 워크플로와 운영 문서, Git 기준의 필수 검사 설명을 함께 갱신한다.
- 실제 GitHub에서 선택 실행과 생략을 확인한 뒤 main, develop의 필수 상태 검사를 `CI Result`로 연결한다.
- 승인 0명, 직접 push 차단, Merge commit 정책은 유지한다.
- 기존 revision 1의 검사와 리뷰는 revision 2의 변경 감지나 최종 판정을 입증하지 않는다. 구현 변경 후 관련 검증과 리뷰를 다시 확보한다.
- 전체 Xcode 부재와 원격 실행 미확인을 빌드 통과로 표시하지 않는다. 원격 확인 전 #3 전체를 완료로 처리하지 않는다.

## 완료 조건

기존 AC 번호를 유지하면서 revision 2의 정의로 갱신하고 추가 기준은 새 번호를 부여한다.
이번 명세 수정 자체가 아래 구현 완료를 의미하지 않는다.

- AC-1: main, develop 대상 PR의 전체 변경을 감지하고 Swift만 변경하면 macOS 빌드만, 웹만 변경하면 웹 검사만 선택한다. 양쪽 변경은 병렬 검사하며 PR 추가 커밋에 선택 결과를 갱신한다.
- AC-2: 기존 npm 명령을 재사용하고, 선택되지 않은 앱의 runner 할당, 의존성 설치, 린트, 타입 검사와 빌드를 생략한다. 하네스 구조 검사와 도구 테스트도 별도로 선택한다.
- AC-3: 선택된 macOS 작업은 macOS 26과 명시한 Xcode 26 환경에서 기존 unsigned 빌드를 실행한다. 웹과 일반 문서만 변경한 PR에서는 macOS 작업을 실행하지 않는다.
- AC-4: 버전 선택, 필요한 의존성 설치와 캐시, 작업별 최소 권한, 시간 제한과 PR 이전 실행 취소를 유지하고 워크플로 정적 검증을 통과한다.
- AC-5: 운영 문서에 변경 영향표, 선택과 생략 이유, `CI Result` 판정, Swift 테스트 부재, 후속 CD와 원격 확인 상태가 정확히 설명된다.
- AC-6: 게시 후 실제 GitHub의 선택 실행과 생략, 최종 판정을 확인하고 main, develop의 필수 검사를 `CI Result`로 연결한다. 원격 확인 전까지 대기 상태로 남긴다.
- AC-7: 루트 잠금 파일, 하네스 문서, 실행 도구, 공통 환경과 CI 정의 변경을 영향표에 따라 분류하며 파일 삭제와 이동도 누락하지 않는다.
- AC-8: 변경 감지나 필요한 검사가 실패, 취소되거나 예상과 달리 생략되면 `CI Result`가 성공하지 않는다. 관련 없는 검사의 의도된 생략은 병합을 막지 않는다.

| AC-7 | 루트 잠금 파일만 변경한 PR | 웹 검사만 실행 |
| AC-2, AC-7 | macOS 실행 도구를 변경한 PR | macOS 빌드와 하네스 검사 실행, 웹 검사 생략 |
| AC-7 | 공통 실행 환경 또는 CI 정의를 변경한 PR | 영향표에 명시된 검사 전체 실행 |
| AC-7 | 파일 삭제, 앱 폴더 간 이동과 이름 변경 | 이전 경로와 새 경로에 영향받는 검사 누락 없음 |
| AC-8 | 감지 실패, 불완전한 목록 또는 필수 출력 누락 | 최종 결과 실패, 변경 없음으로 오인하지 않음 |
| AC-8 | 필요한 검사 실패, 취소 또는 예상 밖 생략 | 최종 결과 실패 |
| AC-8 | 필요한 검사 성공, 관련 없는 검사 생략 | 최종 결과 성공 |
| AC-4 | actionlint와 버전, 권한, 조건, concurrency, timeout 검토 | 정적 검사 통과, 조건에 따른 runner 생략과 실패 전파 유지 |
| AC-5 | 명세, 운영 문서와 Git 기준의 링크 및 정책 검토 | 변경 영향표와 필수 검사 이름 일치, 미검증을 성공으로 표현하지 않음 |
| AC-6 | 후속 실제 PR check runs와 원격 ruleset 조회 | 선택 실행과 생략 및 `CI Result` 판정 확인, 두 대상 브랜치에서 최종 결과 필수 |

이번 문서 변경은 `workflow:harness-check`, 링크와 diff 검토로 확인한다.
앱 빌드나 웹 검사를 실행해 변경 감지 구현을 검증한 것으로 보고하지 않는다.
후속 구현에서는 분류와 결과 판정의 정상 및 실패 사례를 검증하고,
로컬 정적 검사와 실제 GitHub 실행 결과를 구분해 기록한다.

## 미결정 사항

- 제품 정책과 실행 범위의 미결정 사항은 없다.
- 감지 Action의 확정 버전과 SHA, 구체적인 경로 패턴 및 출력 표현은 후속 구현에서 위 영향표와 실패 처리 기준에 맞춰 검증한다.
- 원격 실행과 필수 검사 연결은 게시 후 단계이며 현재는 수행하지 않는다.

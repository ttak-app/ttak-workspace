# 작업 명세: 일정 결과 항목 및 편집 필드 구현

## 연결 정보

- 이슈: #22 / https://github.com/ttak-app/ttak-workspace/issues/22
- 브랜치: feat/schedule-result-item/#22
- specRevision: 10

## 목적

분석 결과 한 건의 제목, 날짜, 선택 시각과 저장 목록을 확인하고 수정하는 SwiftUI View를 구현한다. 사용자가 확인한 시안의 한 항목 영역을 기준으로 한다.

## 작업 범위

### 포함

- 기존 ScheduleDraft 바인딩과 검증을 재사용하는 ScheduleResultItem, 기존 기술 검증 화면 연결
- 안정 ID 기반 편집과 제외 요청, 목록 미선택 및 중복 이름 구분
- 날짜 충돌 확인, 잘못된 날짜, 시각 미지정과 잘못된 시각의 필드별 안내
- 장소와 종료 정보, 모호한 시간 원문을 포함하는 notes 펼쳐 보기와 직접 편집
- 실제 View와 합성 데이터만 사용하는 갤러리 샘플

### 제외

- 여러 항목 결과 패널과 전체 취소, N개 등록 구현
- 분석, 실제 목록 조회와 저장, 저장된 미리 알림 삭제
- 제외 복구 정책, 목록 설명 설정

## 설계 결정

- ScheduleResultItem은 초안 Binding, 목록, Calendar와 UUID 제외 콜백을 받는다. 서비스 및 별도 ViewModel을 만들지 않는다.
- 날짜와 시각은 기존 문자열 모델과 ScheduleDateParser를 유지하되, 날짜 달력 팝오버와 시/분 선택 메뉴로 편집한다. 적용 전 선택은 로컬 상태이며 취소 시 초안을 변경하지 않는다. 날짜 충돌은 유효한 날짜 입력 후 명시적 확정으로 해소한다.
- 시각 빈 문자열은 허용하며 원문을 임의 변환하지 않는다. 선택 불가 목록 ID도 보존하고 안내한다.
- 이름이 중복된 목록은 전체 ID를 표시해 구분한다. 선택 값은 항상 ID다.
- 메모는 DisclosureGroup 안의 여러 줄 입력칸으로 직접 편집하며 draft.notes에 반영한다. 기존 내용은 보존하고, 안내 제목과 빈 메모 안내 대신 입력 placeholder를 사용한다. 검증 안내는 메모 밖에 표시한다.
- 제외는 부모가 isExcluded를 설정하고 표시에서 뺀다. 샘플 초기화는 개발용 기능이며 제품의 제외 복구 정책이 아니다.
- 넓은 화면에서는 필드를 가로로, 좁은 화면에서는 세로로 배치한다. Apple 기본 컨트롤과 기존 브랜드 토큰을 사용한다.
- 결과 카드에는 #21 이미지 첨부 카드와 같은 regular Liquid Glass와 windowBackgroundColor 기반 중립 tint를 적용한다. 내부 필드는 시스템 textBackgroundColor와 separatorColor 경계선으로 구분하고, 갤러리에는 같은 차콜 배경을 사용한다.
- 기준은 로컬 origin/develop @ 784fe01이다. #21을 포함했던 잘못된 분기 상태를 백업한 뒤 #22 변경만 독립 재구성했다. #21 브랜치와 별도 작업 폴더는 수정하지 않았다. origin/develop을 자동 fetch하지 않았다.

## 완료 조건

- AC-1: 제목, 날짜, 시각, 목록과 메모 수정이 전달받은 초안에 반영되고 초안 ID가 유지된다.
- AC-2: 날짜 충돌과 잘못된 날짜, 시각 미지정, 목록 미선택을 구분하고 부가 정보 원문을 확인할 수 있다.
- AC-3: 제외 요청이 초안 ID로 부모에 전달되며 실제 서비스 호출 없이 갤러리에서 확인할 수 있다.
- AC-4: 정상, 충돌, 미지정, 미선택, 긴 제목과 메모, 중복 이름 목록 샘플을 실제 컴포넌트로 제공한다.
- AC-5: Swift 포맷과 빌드, 기존 테스트를 실행하고 직접 편집 동작의 검증 범위와 제약을 보고한다.

## 미결정 사항

- 제외 복구와 목록 설명 설정은 후속 논의로 남긴다. 이번 표시 및 편집 필드 구현을 막지 않는다.

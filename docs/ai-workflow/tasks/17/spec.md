# 작업 명세: 디자인 시스템 구축

## 연결 정보

- 이슈: #17 / https://github.com/ttak-app/ttak-workspace/issues/17
- 브랜치: feat/design-system/#17
- specRevision: 3

## 목적

Apple 기본 컴포넌트를 사용하는 앱과 웹이 Ttak의 브랜드 기준을 공유한다. 랜딩의 모든 CSS 수치를 공통 토큰으로 옮기지 않는다.

## 작업 범위

### 포함

- 브랜드 coral, orange, strong, tint와 로고 coral, orange 및 로고 그라디언트만 유지
- 공통 JSON에서 웹 CSS, macOS 브랜드 Color, 토큰 목록과 시각적 미리보기 생성
- 앱의 기본 텍스트, 배경, 컨트롤과 Liquid Glass는 시스템 스타일 우선이라는 사용 기준
- 브랜드 대비와 용도 제한, 원본 근거 및 생성물 일관성 검사

### 제외

- 기본 텍스트, 배경, 상태색, 간격, 반경, 타이포그래피, 블러, 그림자 및 모션의 공통 토큰화
- UI 컴포넌트 제작, 제품 화면 변경, 기존 랜딩 마이그레이션
- 새로운 폰트, 다크 모드 브랜드 변형, Figma, 라이브러리와 CI 정책
- push, PR 생성, merge

## 설계 결정

- `design-system/tokens.json`의 7개 항목만 관리한다. 중복 원시 팔레트나 의미 없는 별칭을 추가하지 않는다.
- 로고 그라디언트는 두 로고 컬러를 참조한다. macOS에는 브랜드 Color만 내보내며 CSS 각도를 SwiftUI 좌표로 임의 변환하지 않는다.
- 웹의 개별 화면 스타일은 해당 CSS에서 관리한다. 앱은 Apple 기본 컴포넌트의 글자, 배경과 재질을 우선 사용하고 필요한 브랜드 강조에만 토큰을 검토한다.
- 기존 생성 명령과 참조 검사를 유지하고 미리보기에는 현재 채택한 토큰과 시스템에 맡길 항목을 보여준다.
- 분석용 원본 스냅샷은 근거로만 유지한다. 제품 또는 활성 토큰 목록이 아니다.
- 상태 흐름: JSON → 참조 검사 → CSS, Swift Color, 목록, 미리보기. 제품 상태 변경 없음.
- 예외 처리: 참조 누락과 순환, 타입 및 변수명 충돌, 생성물 차이는 실패로 처리한다.

## 완료 조건

- AC-1: 활성 토큰이 브랜드 4색, 로고 2색 및 로고 그라디언트의 7개로 축소되고 출처와 용도를 확인할 수 있다.
- AC-2: 웹과 macOS 출력에 제거한 텍스트, 배경, 크기 및 효과 토큰이 남지 않는다.
- AC-3: 생성과 참조 검사가 통과하고 브랜드 대비 측정 도구가 삭제한 토큰을 참조하지 않는다.
- AC-4: 사용 지침과 미리보기가 Apple 시스템 스타일 우선 원칙과 브랜드 용도 제한을 설명한다.
- AC-5: 기존 화면을 변경하지 않고 작은 커밋으로 기록하며 웹 검사, macOS 빌드와 미리보기 화면 확인이 완료된다.

## 미결정 사항

- 브랜드의 다크 모드 변형과 실제 앱 화면별 tint 적용은 후속 검토 대상이다. 고정 브랜드 Color가 시스템 적응 색상이라는 뜻은 아니다.
- 공통 간격과 반경은 실제 반복 사용 근거가 생길 때만 추가를 검토하며 현재는 도입하지 않는다.

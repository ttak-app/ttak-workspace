# 핵심 키워드 제목 설계

사용자가 원문 구절에 가까운 제목 대신 다음 짧은 제목을 요구했다.

- 민수 온라인 줌 미팅
- 지수 합정 점심
- 도서관 자료조사
- 독서모임 회식

## 변경할 계약

모델은 독립 일정별 `sourceText`만 생성하고 연속 원문 전체를 보존한다. Swift가 이 구간의 날짜와 시각을 구분한 뒤, 인식 가능한 행동에 한해 인물과 장소, 진행 방식과 도구 및 행동을 제목 키워드로 자동 조합한다. `titleKeywords`는 모델 생성 필드가 아닌 내부 후처리 값이다. 날짜와 시간 및 조사와 문장 표현은 제목에서 제외하고 상세 대상 및 부가 정보는 원문 메모에 보존한다.

날짜와 시각 추출은 계속 Swift에서 수행한다. 모델에 날짜 계산과 목록 추천을 다시 맡기지 않으며 추가 제목 전용 호출이나 일정별 호출을 만들지 않는다. 기존 최대 한 번의 재분석을 유지한다.

## 제목 검증

- 제목 키워드는 해당 일정 원문에서 확인한다. 원문 공백을 붙인 복합 명사 표현은 허용한다.
- 사용자 예시처럼 회의 또는 줌 문맥의 행동을 `미팅`으로 표현할 수 있다. 아무 검토 행동이나 미팅으로 바꾸는 규칙은 추가하지 않는다.
- 제목에서 일부 세부 정보를 생략할 수 있지만 같은 일정의 원문은 메모에 남긴다. 기존의 모든 의미 단어를 제목에 포함해야 한다는 검사는 새 키워드 제목 경로에 적용하지 않는다.
- 다른 일정의 인물과 장소나 원문에 없는 행동은 허용하지 않는다. 부정과 취소 및 확인 여부처럼 행동의 의미를 바꾸는 표현은 제목에도 유지하도록 검사한다.
- 날짜와 숫자 시각을 제목 키워드로 넣지 않는다. `내일신문` 같은 고유명사 전체는 시간 단어와 구분한다.
- 자동 축약 근거가 부족하거나 부정과 취소 및 확인 의미가 있으면 기존 원문형 제목을 유지한다. 생성된 제목의 근거 검증이 실패하면 기존 재분석과 보류 경로를 사용하고 사람이 원하는 값을 대신 넣지 않는다.

## 검증

사용자가 제시한 네 제목을 핵심 목표로 고정하고 동일한 어려운 입력에서 실제 모델 원문 분리와 자동 후처리를 합친 최종 제목을 확인한다. 날짜와 시각 및 일정 수를 함께 비교한다. 별도의 부정과 취소 문장, 새로운 인물과 장소 및 실제 OCR 텍스트에서도 의미 보존과 잘못된 제목 거부를 확인한다. 코드 단위 테스트와 실제 모델 출력은 구분한다. 미리 알림 저장과 커밋 및 게시는 포함하지 않는다.

## 결합 생성 실험과 후속 대안

원문과 키워드를 같은 호출에서 생성하는 첫 두 실험은 채택하지 않았다. 일부 목표 제목은 생성했지만 원문 구절을 요약해 누락하거나 다른 일정의 단어를 섞고 중요 부정을 빠뜨렸다. 앱의 기본 원문 추출은 검증된 이전 계약으로 복원했고 실패한 소스와 응답은 로컬 실험 스냅샷에 보존했다.

이미 검증한 일정별 원문을 입력으로 제목만 생성하는 추가 실험도 비교했다. 예시를 포함한 지침은 일부 예시 문구를 다른 일정에 덧붙였고, 예시를 제거한 지침도 핵심어 누락과 원문에 없는 도구 추가가 있었다. 사람의 수정으로 목표 제목을 만든 결과는 없다.

후속 대안은 기존 원문 분리와 날짜 및 시각 처리를 유지하고, 모든 일정의 제목을 한 번에 고르는 추가 호출이다. 일정마다 해당 원문에서 확인한 제한된 어휘만 생성 스키마에 허용해 다른 일정의 인물이나 없는 단어 생성을 막는 방식을 실험한다. 이 방식은 정상 분석에 모델 호출이 한 번 추가되는 tradeoff가 있다. 스키마 제약이 핵심어의 올바른 선택이나 고유명사의 형태 및 부정 의미 보존까지 보장하지 않으므로 실제 품질과 별도 검증을 확인한 뒤 채택한다.

## 채택한 자동 후처리

제한된 어휘의 선택 실험도 온라인 방식과 합정 장소를 누락했고, 부정 의미는 별도 보존 경로가 필요했다. 추가 모델 호출을 도입하지 않고 원문 분리 계약을 유지한다. Swift에서 `미팅`, `자료조사`, `자료정리`, 식사와 회식 등 인식한 종결 행동만 축약한다. 줌 문맥의 검토를 미팅으로 표현하는 것은 사용자 예시에 따른 제한적 별칭이다. 이 방식은 학습이나 일반적인 한국어 형태소 분석기가 아니다.

인물의 동반 조사와 장소의 `에서`, 명시된 온라인 방식과 줌 도구를 원문에서 얻어 인물, 장소, 방식, 도구, 행동 순서로 조합한다. 같은 일정 원문에 없는 키워드는 거부하며 모든 상세 정보는 원문 메모에 보존한다. `역 앞에서`처럼 단편만으로 장소를 정할 수 없는 경우, 인식하지 못한 행동 및 부정과 취소 여부 확인은 원문형 제목을 유지한다. 고유명사와 조사가 겹치는 모든 표현을 해결한 것으로 간주하지 않는다.

관찰 기록은 모델 원시 응답과 Swift `title-formatting`을 구분한다. 축약 경로의 값이 빈 배열이면 원문형 제목을 사용했다는 뜻이며 모델이 짧은 제목을 생성했다는 근거가 아니다.

# 텍스트 일정 분리 가드 개선 설계안

- 연결 이슈: [#15](https://github.com/ttak-app/ttak-workspace/issues/15)
- 기준 커밋: `381b4e1`
- 작성일: 2026-10-27
- 상태: 사용자 승인 후 specRevision 4로 구현하고 2차 실제 모델 비교를 진행했다. 아래 제안은 설계 기록이며 실제 구현 차이와 결과는 문서 끝 및 [2차 결과](round2-results.md)를 기준으로 한다.
- 목적: 1차 실측에서 나온 일정 혼입, 누락, 시각 생성과 선택 범위 오류를 줄이고, 검증할 수 없는 결과를 확정값으로 넘기지 않는다.

## 1차 기준 시점의 결과와 한계

| 관찰 또는 코드 확인 | 현재 보완 | 남은 한계 |
| --- | --- | --- |
| 단일 회의 입력에서 지침의 런닝 예시가 추가됨 | 구체 일정 예시 제거, 필드 지침 보완 | 제목과 행동의 원문 근거를 코드에서 검사하지 않음 |
| 런닝과 회식 두 행동이 한 항목과 메모로 합쳐짐 | 독립 행동 분리 지침 보완, 대표 예제 재확인 | 누락된 행동을 별도 검증하는 절차 없음 |
| 원문에 없는 시각 생성 | 원문 시각 대조와 코드 정규화 | 현재 검색 범위는 입력 전체이며 일정별 귀속 근거가 없음 |
| 제목에 날짜와 시각이 그대로 포함됨 | 편집 가능한 초안 제공 | 제목과 날짜 및 시각의 분리 기준이 약함 |
| 이미지에서 회의만 선택 요청이 무시됨 | OCR과 사용자 설명 분리, 선택 호출 추가 | 유효한 후보 인덱스라도 의미상 올바른 선택인지는 코드만으로 증명할 수 없음 |
| 내일과 모레가 시작 시각 원문으로 반환됨 | 실제 시각으로 변환하지 않고 확인 메모 추가 | 날짜 표현과 시각 표현의 필드 혼동이 남음 |

수정 후 소규모 합성 예제는 개선되었지만 전체 한국어 정확도나 오류 재발 방지를 증명한 것은 아니다. 기존 Swift 테스트 27개는 주로 검증 로직과 상태 흐름을 확인하며 실제 모델의 의미 분리 정확도 점수가 아니다.

## 제안 흐름

`입력 원문 유지 → 행동 후보와 필드 근거 추출 → 코드 가드 → 필요한 경우에만 오류 범위 재분석 → 날짜 및 시각 정규화 → 편집 가능한 초안`

원문은 읽기용으로 보존한다. 정규화한 문자열을 사용할 경우 원문 위치와 대응시킨다. 코드가 반환한 후보 식별자를 사용자 선택 및 후속 모델 호출에 사용한다. 모델에게 한글 문자열의 문자 오프셋 계산을 맡기지 않는다.

## 1. 행동과 필드에 원문 근거 연결

추출 후보에는 일정의 행동 근거, 제안 제목, 날짜 표현, 시작 시각 표현, 장소와 메모 근거를 구분해 받는 안을 제안한다. 근거는 입력에서 복사한 원문 조각이고, 코드는 해당 조각의 실제 위치를 확인한다. 여러 위치에 같은 표현이 있으면 임의로 첫 위치에 연결하지 않는다.

- 행동 근거가 입력에 없으면 해당 후보를 정상 일정으로 채택하지 않고 재분석 대상으로 보낸다.
- 시작 시각은 해당 행동의 근거 구간 또는 검증된 공유 문맥에 연결되어야 한다. 입력 어딘가에 같은 시각이 있다는 이유로 채택하지 않는다.
- 날짜는 직접 표현과 앞선 문맥에서 이어받은 표현을 구분한다. 공유 날짜는 하나의 근거를 여러 일정이 참조할 수 있다.
- 장소와 메모도 해당 일정의 근거에 연결한다. 동일한 장소나 날짜를 공유한다는 이유로 중복 일정으로 판단하지 않는다.
- 원문 포함 여부는 출처를 확인할 뿐, 그 구절이 실제 행동인지 또는 모델의 해석이 맞는지까지 증명하지 않는다.

예: `내일 오전 9시 런닝하고 저녁에 회식`에서 런닝과 회식의 행동 근거를 나누고, 내일은 공유 날짜로 참조한다. 오전 9시는 런닝에만 연결한다. 회식의 저녁은 정확한 시각으로 바꾸지 않고 보존한다.

## 2. 문장 분리와 누락 및 중복 의심 검사

연결어, 줄바꿈, 새 날짜와 시각 표현은 분리 후보를 찾는 단서로 사용한다. 연결어 수를 일정 수로 확정하지 않는다. `디자인 및 개발 회의`처럼 제목 내부의 연결과 독립 행동의 연결은 구분해야 한다.

- 서로 다른 행동 근거가 한 후보의 메모에만 들어 있거나, 분리 단서가 있는 입력에서 하나의 행동만 대응되면 누락 의심을 기록한다.
- 같은 행동 근거와 같은 날짜 및 시각을 중복 참조한 후보는 중복 의심으로 기록한다. 제목만 같다는 이유로 자동 병합하지 않는다.
- 한 후보가 원문 전체를 근거로 반환했다는 사실만으로 누락 검사를 통과시키지 않는다.
- 근거가 없는 부분이나 연결어가 남았다는 이유만으로 새 일정을 자동 생성하지 않는다. 장소와 준비물 같은 부가 정보는 일정이 아닐 수 있다.
- 코드의 의심 검사로 모든 누락과 잘못된 분리를 탐지할 수는 없다. 탐지하지 못한 의미 오류는 실제 모델 회귀 예제로 평가한다.

## 3. 날짜와 시각의 역할 가드

- 날짜와 시각 표현을 별도 필드로 받는다. `내일`, `모레`가 시작 시각 근거로 오면 시각으로 채택하지 않는다.
- 오늘, 내일과 모레의 근거가 검증되면 분석 실행 시점의 고정된 달력과 시간대로 계산한다. 모델이 만든 임의 dayOffset를 근거 없이 신뢰하지 않는다.
- 새 날짜 표현이 있으면 해당 표현의 적용 관계를 확인한다. 모든 뒤 항목에 마지막 날짜를 무조건 복사하지 않는다. 해석이 모호한 문장의 범위는 확인 대상으로 남긴다.
- 시작, 종료와 메시지 발송 시각을 구분한다. 종료만 있는 표현은 시작 시각을 채우지 않는다.
- 표현 자체가 없는 것과, 명확한 표현이 있지만 파서가 처리하지 못한 것을 구분한다. 후자는 단순 미지정으로 숨기지 않고 확인 이유를 남긴다.
- `nil` 같은 모델의 자리표시 문자열이나 날짜 구절을 잘못된 시작 시각 안내로 그대로 노출하지 않는다. 원문과 필드 역할을 확인해 표시한다.

## 4. 제목과 선택 범위 가드

제목은 행동을 드러내는 원문을 우선 사용하고, 근거가 확인된 날짜와 시각 구간만 분리하는 안을 제안한다. 문자열에서 날짜처럼 보이는 단어를 일괄 삭제하지 않는다. `9시 뉴스 시청`처럼 시각 표현이 제목 의미의 일부일 수 있다. 제목을 간결하게 만드는 기준이 불명확하면 원문을 유지해 편집 가능하게 둔다.

사용자 설명과 분석 대상 자료는 계속 분리한다. `회의 말고 점심만 등록`의 제외 지시와 `회의 취소하기`라는 실제 행동은 다르므로 취소와 제외 키워드만으로 후보를 삭제하지 않는다. 선택 결과는 기존 후보만 참조하도록 검사하고, 실패했다고 전체 후보를 반환하지 않는다. 선택 모델의 자체 확신 점수는 검증 통과 기준으로 쓰지 않는다.

## 5. 가드 위반 처리와 호출 비용

| 결과 | 제안 처리 |
| --- | --- |
| 필드 근거와 관계가 유효함 | 코드 정규화 후 초안으로 전달 |
| 모호한 시각처럼 정책상 미지정이 허용됨 | 시각을 채우지 않고 원표현 보존 |
| 원문에 없는 행동, 누락 및 중복 의심, 필드 귀속 충돌 | 위반 이유와 관련 원문을 포함해 해당 범위만 재분석 |
| 재분석 후에도 분리 관계가 불명확함 | 확정하지 못한 이유를 초안에 표시. 새 항목 생성이나 조용한 삭제로 해결하지 않음 |
| 형식 또는 선택 결과가 유효하지 않아 초안 구성이 불가능함 | 원인을 구분해 실패를 안내하고 입력 유지 |

재분석은 가드 위반이 있을 때만 최대 한 번을 우선 제안한다. 모든 입력에 검토용 모델 호출을 추가하지 않는다. 기존 보조 설명 선택 호출과 중복되지 않도록 구현 시 실제 호출 흐름을 확인한다. 반복 호출은 정확성 보장이 아니며 무한 재시도하지 않는다.

새 확인 상태에서 등록을 허용할지, 어떤 항목을 보류할지의 제품 UX는 후속 결정 사항이다. 이 설계안으로 기존의 편집 및 등록 정책을 자동 변경하지 않는다.

## 구현 및 검증 순서 제안

1. 1차 실패 사례와 유사한 합성 문장을 회귀 예제로 고정한다. 기존 결과와 비교 가능한 기대 행동, 날짜, 시각, 선택 대상을 기록한다.
2. 행동 및 필드 근거를 갖는 추출 계약과 코드 검증을 먼저 구현한다. 원문 위치의 중복과 공유 날짜를 포함해 검증한다.
3. 날짜와 시각 귀속, 제목 혼입, 누락 및 중복 의심 처리를 순서대로 추가한다.
4. 실제 오류가 탐지된 범위에만 한 번의 재분석을 연결하고, 여전히 불명확한 결과의 확인 UX를 정한다.
5. 합성 회귀 예제로 실제 모델의 행동 분리와 누락 및 과다 추출을 대조하고, 처리 시간과 호출 횟수 변화도 관찰한다.

회귀 예제는 단건, 복수 행동, 공유 날짜, 서로 다른 날짜, 모호한 시각, 종료만 있는 표현, 선택 및 제외 요청, 반복 제목과 비일정 정보를 포함한다. 개선에 사용하지 않은 유사 표현도 포함해 특정 예문만 맞추는 변경을 피한다.

비교 지표는 과다 추출 건수, 누락 건수, 필드 오연결, 날짜와 시각 정답 여부, 선택 결과 및 불필요한 확인 증가를 구분한다. 오류를 줄인다는 이유로 모든 결과를 보류하는 변경도 개선으로 계산하지 않는다. 일반 정확도 목표나 통과율 수치는 이번 소규모 결과만으로 정하지 않는다.

코드 검증의 회귀는 기존 Swift Testing에서 실행한다. 실제 시스템 모델 평가는 별도 로컬 실행 기록으로 남기며 일반 CI의 단위 테스트 통과와 구분한다. 미리 알림 쓰기는 이 분석 개선 평가에 필요하지 않다.


## 2차 구현 반영

- `GroundedSchedule`로 행동 구간과 제목, 날짜, 시작 시각 및 메모를 분리해 받고 Swift에서 실제 원문 위치를 대조한다. 동일 제목도 서로 다른 원문 위치이면 유지한다.
- 최초 가드 위반 후에는 행동 목록만 추출하는 단순한 구조로 한 번 재분석한다. 전체 입력을 다시 사용하며, 앞선 오류 구간만 편집하는 부분 재분석은 구현하지 않았다. 실패한 복잡한 필드 추출을 반복하는 대신 코드가 날짜와 시각 근거를 다시 연결한다.
- 가드 위반이 계속되면 `일정 분리 확인 필요` 오류로 반환하고 기존 입력을 유지한다. 검증한 후보만 조용히 남기는 부분 성공은 추가하지 않았다. 날짜만 미지원이거나 충돌하면 기존 날짜 확인 상태를 사용한다.
- 재분석에서 목록을 추측하지 않고 미선택으로 둔다. 원문에서 복원한 행동 구간을 메모에 보존하지만 별도 장소 및 인물 필드의 완전한 보존은 보장하지 않는다.
- 상대 날짜의 조사 경계, `오전 9시 반`과 실제 행동 `메시지 발송`을 메타정보와 구별하는 회귀도 추가했다.
- 보조 설명이 있을 때의 기존 후보 선택 호출은 유지한다. 일반 입력은 추출 1회, 가드 위반 입력은 최대 추출 2회이며 보조 설명이 있으면 선택 호출 1회가 추가될 수 있다. 단위 테스트에서 재분석 상한을 확인했다.

[2차 결과와 한계](round2-results.md), [Notion 개발 문서](https://app.notion.com/p/406f8dfb2e3c81ea8f25f92a853777e9)에 비교 근거를 정리한다. 실제 메뉴바 UI, EventKit 권한과 저장 대조를 완료했다는 뜻은 아니다.


## 2차 이후 코드 정리, 실제 모델 테스트 대기

프롬프트만 수정한 뒤 사용자가 모델 테스트 전 코드 정리를 요청해 제목 후처리와 24시간제 변환을 연결했다. 최초 추출과 행동 재분석에서 `actionText` 원문과 `titleParts` 제목 조각을 함께 받는다. 별도 인물 분류 필드나 추가 호출은 만들지 않았다.

`actionText`의 원문 근거를 먼저 확인한 뒤 제목 조각의 순서, 빠진 구간과 남은 단어를 검사한다. 조각 사이의 공백과 제한된 조사만 제거할 수 있다. 의미 단어가 빠지거나 원문에 없는 단어 및 재배열이 있으면 가드 위반이다. 조각이 없으면 원문 행동 구절을 유지한다. 원문 전체에 조사 정규식을 일괄 적용하지 않는다.

오전과 오후 없는 숫자 시각은 24시간제로 해석하고 명시적인 오전과 오후는 우선 적용한다. 숫자 없는 저녁이나 종료 및 메시지 시각은 시작 시각으로 바꾸지 않는다. 행동 재분석은 시간대 표현도 구간 경계에 포함하며 다음 행동 바로 앞 시간대가 이전 후보 끝에 붙는 경우를 검사한다.

실제 모델 호출은 계속 보류한다. 코드와 대체 응답의 검증 범위 및 모델 테스트 전 상태는 [준비 기록](pre-model-preparation.md)을 따른다. 위의 2차 실제 모델 비교 수치를 새 프롬프트와 계약의 통과 근거로 재사용하지 않는다.


## 2026-10-28 제목 정리 규칙 수정

무편집 저장에서 문장 표현과 공백 문제가 확인돼 프롬프트, 가드 및 제목 조립 코드를 함께 수정했다. `ScheduleTitleNormalizer`로 순수 변환을 분리하고 원문 근거를 보존한 채 표시값을 정리한다. 아래는 코드의 합성 응답 테스트 대상이며 실제 모델 재검증 결과가 아니다.

- 제한된 문장 끝 표현은 제목 조각에 포함돼 있어도, 모델이 생략해도 같은 규칙으로 처리한다. 원문 근거와 부정 및 취소 의미는 유지한다.
- 원문에서 붙은 조각은 다시 붙여 `가상동 에서` 같은 새 공백을 만들지 않는다. 원문의 띄어쓰기를 일반적으로 교정하는 기능은 아니다.
- 최초 추출과 행동 재분석에 `locationText`를 추가했다. 같은 후보 원문에서 위치를 구별할 수 있는 실제 장소 이름만 제목에서 메모의 장소 안내로 이동한다. 온라인 진행 방식과 도구 이름은 장소로 취급하지 않는다.
- 예를 들어 합성 원문의 인물과 점심 약속은 제목에 남고, 실제 장소 표현은 메모와 원문에 보존된다. 미리 알림의 구조화된 장소 API는 이번에 추가하지 않았다.
- 문장 표현 제거는 한정된 목록과 위치 조건을 사용한다. 이동 동사와 부정이 의심되는 경우 원문을 보존한다. 고유명사와 의미 역할을 모든 표현에서 증명하는 형태소 분석기는 아니다. 모델의 잘못된 역할 분류는 후속 실제 검증에서 확인해야 한다.
- 의미 단어를 빼거나 재배열한 제목, 원문에 없는 장소와 같은 이름의 모호한 위치, 장소만 남은 후보를 거부하는 회귀를 포함한다. 재분석 상한과 날짜 및 시각 규칙은 유지한다.

이번 수정에서는 모델을 호출하거나 미리 알림에 추가 저장하지 않는다. 기존 실제 저장 결과를 새 코드의 모델 품질 통과 근거로 사용하지 않는다. 기록은 `.tmp/ai-workflow/tasks/15/title-cleanup/`의 검사 및 검토 근거를 따른다.

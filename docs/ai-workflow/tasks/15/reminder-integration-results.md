# #15 미리 알림 저장 연동 확인

- 실행일: 2026-10-27
- 대상 커밋: `2abe1e5`
- 범위: 첫 검증은 편집한 최종값의 저장이며, 뒤의 후속 검증은 실제 모델 초안의 무편집 저장이다. 두 결과를 구분한다.
- 3차 모델 품질 비교는 실행하지 않았다. 사용자가 이번 연동 확인에 제공한 입력 한 건만 현재 분석 서비스로 실행했다.

## 실행과 결과

| 단계 | 관찰 |
| --- | --- |
| 분석 결과 | 같은 날짜의 3건, 09:00과 12:00 및 18:00 추출 |
| 최종값 편집 | 제목에 남은 문장 끝 표현을 정리하고 두 번째 일정의 장소를 메모에 명시적으로 보존 |
| 권한과 목록 | 검증 실행 도구의 실제 접근 허용 및 쓰기 가능한 목록 조회 성공. 사용자가 지정한 기존 목록 선택 |
| 저장 | 앱과 같은 `ReminderStore.save` 소스로 구분 가능한 테스트 항목 3건 생성 |
| 재조회 | 새 EventKit 저장소에서 생성된 ID만 조회해 제목과 날짜, 시각, 메모 및 목록이 모두 일치하는지 확인 |
| 사용자 화면 대조 | 사용자가 Apple 미리 알림 앱에서 3건과 날짜, 시각 및 장소 메모 일치를 확인 |

저장 직전에 로컬 영수증 파일을 예약하고 각 생성 ID를 기록했다. 같은 저장 실행의 재호출은 막으며, 결과 불명 시 자동으로 재저장하지 않는다. 실제 생성은 한 번만 실행했다. 목록을 새로 만들거나 기존 항목을 수정 및 삭제하지 않았다. 테스트 항목은 확인 후에도 유지한다.

원시 분석 제목에는 문장 끝 표현과 부자연스러운 공백이 남았다. 편집한 최종값의 저장 성공을 모델 제목 정리 품질의 성공으로 해석하지 않는다. 실제 저장에서 장소 메모가 보존된 것도 최종 편집값을 기준으로 확인했다.

## 검증 경계

Ttak 앱은 실행됐으나 화면 제어 도구가 시간 초과되어 메뉴바 UI를 조작하지 못했다. 원본 앱과 같은 저장 서비스 소스를 별도 로컬 도구로 컴파일해 실행했다. 이 도구는 자체 권한 식별자를 사용하므로 Ttak 앱 번들의 권한과 sandbox 및 등록 버튼 동작을 검증했다고 하지 않는다.

이번 결과는 실제 저장 API 연결과 최종값 보존 및 Apple 미리 알림 화면 대조의 근거다. AC-3의 서비스 및 저장 대조 부분을 확인했지만 앱 자체의 권한 동작과 등록 UI 확인은 남아 있다. OS 권한을 실제 거부하는 실험, 이미지 파일 선택과 붙여넣기 등록 경로 및 macOS26 실기기 검증도 포함하지 않는다.

## 로컬 증거

개인 입력과 참여자 및 장소, 목록 이름과 ID 및 저장된 항목 ID는 공유 문서에 복사하지 않는다. Git에서 제외한 `.tmp/ai-workflow/tasks/15/eventkit-integration/`에만 둔다.

- `single-analysis.json`: 단일 실제 분석 응답
- `confirmed-drafts.json`, `edit-record.json`: 저장할 최종값과 편집 내역
- `save-receipt.json`: 생성 ID와 재조회 대조 결과. 재저장 방지 근거
- `source-sha256.json`: 사용한 앱 서비스 소스 지문
- `observation.log`: 실행 방식과 사용자 화면 대조 및 미검증 기록
- `ReminderIntegrationProbe.swift`, `SingleInputAnalysis.swift`: 별도 실행 도구 소스

앱 소스는 이번 연동 확인에서 변경하지 않았다. 모델의 제목 정리 개선과 Ttak UI를 통한 최소 등록 확인은 후속으로 남긴다.


## 후속 검증: 모델 초안 무편집 저장

사용자가 제목을 직접 정리한 첫 검증의 한계를 지적해, 실제 분석 결과를 수정 없이 저장하는 흐름을 추가로 실행했다. 앱 소스는 변경하지 않았다.

별도 검증 실행 파일에서 실제 `ScheduleInputModel`과 `ScheduleAnalyzer`, `ReminderStore`를 함께 사용했다. `loadLists → startAnalysis → waitForAnalysis → 저장 대상 목록 선택 → saveConfirmedDrafts` 순서를 그대로 실행했다. 저장소를 감싼 관찰 도구는 들어오는 초안이 원본과 같은지 확인하고 원본 저장 서비스를 호출하며 생성 ID만 기록한다. 내용을 보정하지 않는다.

| 확인 항목 | 실제 결과 |
| --- | --- |
| 실제 모델과 앱 분석기 실행 | 제공된 입력 1건에서 초안 3개 반환, 약 15.13초 |
| 날짜와 시각 | 2026-10-27, 09:00과 12:00 및 18:00 |
| 분석 결과에서 저장 직전까지 | 제목, 날짜, 시각, 메모와 확인 상태, 제외 상태 및 초안 ID 유지. 사용자 지정 목록 ID만 대입 |
| 실제 저장과 재조회 | 3건 생성 후 새 EventKit 저장소에서 내용 일치 확인 |
| 표시용 추가 문구 | 테스트 접두사와 검증 ID를 제목 및 메모에 추가하지 않음 |
| 독립 대조 | 로컬 JSON을 다시 읽어 분석 결과와 저장 입력 및 재조회 값의 일치 확인 |
| 사용자 화면 대조 | 2026-10-28 사용자가 수정되지 않은 제목 3건의 표시를 확인. 저장 항목의 날짜는 2026-10-27 |

이번 원시 제목에는 `갈거야`, `있어` 등의 문장 표현과 부자연스러운 공백이 그대로 남았다. 원문 메모에는 일정 연결어가 남는 경우도 있다. 장소 표현은 원래 제목과 원문 메모에 포함되었으며, 별도 장소 안내나 미리 알림의 구조화된 장소 필드를 추가하지 않았다.

**분석 결과를 수정 없이 전달하고 저장하는 연결은 확인했으며, 제목 정리 품질은 부족하다.** 이 두 판정을 구분한다. 모델 초안이 저장 검증에 막히면 값을 보정하거나 확인 상태를 해제하지 않고 중단하도록 했다. 전체 3차 품질 비교나 프롬프트 재조정은 실행하지 않았다.

원시 입력과 출력 및 생성 ID는 공유 문서에 복사하지 않는다. 로컬 `.tmp/ai-workflow/tasks/15/direct-integration/`에 검증 실행 소스, 실행별 `input.txt`, `receipt.json`, `source-sha256.json` 및 `independent-audit.json`을 보관한다. 기존 테스트 항목을 변경하거나 지우지 않고 새 결과만 한 번 생성했다.

이 실행도 자체 권한 식별자의 별도 도구를 사용했으므로 Ttak 메뉴바 화면의 조작과 앱 번들의 권한 및 sandbox 검증은 남아 있다. 실제 앱 상태 모델을 사용해 분석과 저장의 연결을 확인한 근거다.

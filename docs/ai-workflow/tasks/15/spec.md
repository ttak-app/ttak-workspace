## 목적

Gemini API가 한국어 자연어에서 일정별 원문을 추출하고 기존 Swift 가드와 후처리가 날짜, 시각과 제목을 다룰 수 있는지 검증한다. 실제 API 결과, 대체 응답 테스트, 실제 앱 화면과 저장의 검증 여부를 구분한다. 개인 키로 Gemini를 직접 호출하는 경로는 로컬 개발 및 기술 검증용이다.

## 작업 범위

### 포함

- `gemini-3.5-flash-lite` 개발용 설정, 환경 변수로 API 키 읽기 및 JSON 구조화 응답 연결.
- 일정별 원문 추출, 보조 설명에 따른 후보 선택 경로 및 원문 가드, 최대 한 번의 가드 재분석.
- Swift의 상대 날짜와 시각 처리, 명확한 시간 범위의 시작 시각 및 밤 12시의 날짜 귀속.
- 합성 응답 테스트, 실제 Gemini API의 합성 텍스트 평가, 실패와 한계 기록.
- 변경 코드 리뷰와 포맷, 빌드, 자동 테스트 및 작업 기록 확인.

### 후속 작업 및 이번 검증 제외

- 실제 메뉴바 앱 화면에서 Gemini 분석과 sandbox 네트워크 동작 검증, UI 컴포넌트 완성.
- 실제 앱의 EventKit 권한 및 목록, 사용자 선택 항목 저장과 미리 알림 화면 대조. 저장 대상은 실행 시 사용자가 선택한다.
- 실제 앱의 이미지 파일 선택과 붙여넣기, OCR 및 보조 설명을 포함한 Gemini 연동과 등록 경로 검증.
- 제목의 장소 및 `저녁` 누락, 메모 중복의 품질 개선. 429와 503 오류 안내 및 재시도 정책.
- 배포 전 서버, 사용자 인증, 공용 API 키 보호, 사용량과 비용 관리 및 개인 데이터 전송 안내. 현재 직접 호출은 배포용 구조가 아니다.
- 실제 사용자 입력의 정확도 평가, UI 완성 및 배포와 부분 저장 복구 UX.

기존 명세의 실제 미리 알림 저장 조건(이전 AC-3), 이미지 선택 및 붙여넣기 조건(이전 AC-4), 저장 실패 및 부분 성공 검증(이전 AC-5)은 이번 브랜치의 완료 조건에서 제외하고 위 후속 범위로 옮긴다. 기존 코드와 과거 관찰은 삭제하지 않는다. 이전 명세와 이력은 Git의 `cb37966` 및 [기존 구현 기록](implementation.md), [미리 알림 저장 연동 확인](reminder-integration-results.md), [온디바이스 추출 개선 결과](on-device-extraction-results.md)를 따른다.

## 설계 결정

- 모델은 일정별 연속 원문을 반환한다. 원문 내용과 보조 설명은 Gemini 서버로 전송된다. Swift가 원문 근거와 누락, 날짜 및 시각 귀속을 확인하고 제목을 조합한다.
- 가드 위반 시 최대 한 번 재분석하며 계속 검증되지 않으면 초안을 임의 보정하지 않고 보류한다. 네트워크 오류는 성공으로 처리하지 않는다. 서비스 오류 자동 재시도는 후속 작업이다.
- `오후 1시부터 3시까지`처럼 명확한 범위는 시작 시각 `13:00`을 사용하고 전체 원문을 메모에 보존한다. 시작 후보가 여러 개이거나 종료 시각만 있는 경우에는 시작을 임의 확정하지 않는다.
- `밤 12시`와 `밤 12:00`은 해당 날짜의 24시로 해석해 다음 날짜의 `00:00`으로 표시한다. 날짜가 불확실하면 확정하지 않는다. `밤 1시`와 `밤 12시 30분`은 이번 규칙에 포함하지 않는다.
- 숫자로 명시된 시작 시각을 해석할 수 없거나 시작 후보가 여러 개면 해당 표현을 안내하며 전체 분석을 보류한다. 모델의 원문 복사 오류와 구분해 이 사유로 추가 API 호출을 하지 않는다. 종료 및 메시지 메타정보의 시각은 시작 후보에서 제외한다. 숫자가 없는 시간대는 기존 미지정 정책을 유지한다.
- `2시간`과 같은 소요 시간은 시작 시각으로 취급하지 않고 원문 제목에 보존한다. 시작 후보가 여러 개인 경우와 해석할 수 없는 시각의 안내를 구분한다.
- `3시로부터 2시간 후`와 같은 숫자 기반 상대 시간은 기준 시각을 실제 시작으로 확정하지 않고 확인 안내로 보류한다. 현재 범위에서는 상대 시간 계산을 추가하지 않으며 이 사유로 모델 재호출을 하지 않는다. 단순 소요 시간과 구분한다.
- `와`, `과`가 인물 조사인지 단어의 일부인지 구분할 수 없으면 제목 축약을 포기하고 원문형 제목을 유지한다.
- 개발 실행에서 키는 환경 변수로 전달한다. `.env`와 편집기 기록은 Git에서 제외하며 키나 개인 원문을 로그와 공유 문서에 남기지 않는다.

## 완료 조건

- AC-13: Gemini 구조화 응답을 기존 원문 가드와 후보 선택에 연결하고 키 누락, HTTP 오류, 미완료 응답을 실패로 처리한다. 합성 테스트와 실제 API 관찰을 구분한다.
- AC-14: 명시적 시간 범위의 시작 시각, 제목과 전체 원문 메모 보존을 합성 테스트로 확인한다. 종료 시각만 있는 표현과 복수 시작 후보의 기존 경계를 유지한다.
- AC-15: 오늘과 내일의 밤 12시 및 연말에서 다음 해로 넘어가는 사례를 합성 응답으로 확인한다. 기존 오전 12시와 미정 표현의 경계를 유지한다.
- AC-16: 현재 변경을 대상으로 Swift 포맷, macOS 빌드와 자동 테스트 및 하네스 검사를 실행한다. 합성 사례의 실제 모델 결과와 오류 및 한계를 기록한다.
- AC-17: 브랜치 변경을 검토하고 해결하지 않은 결함 및 후속 작업을 명시한다. 실제 앱 UI와 저장, 이미지 경로의 미검증을 통과로 표시하지 않는다.
- AC-18: 해석 불가능한 명시적 시작 시각은 오류로 분석을 보류하고 추가 모델 호출을 하지 않는다. 종료 전용 및 메타정보 시각과 정상 시각은 잘못 보류하지 않으며 여러 일정 중 하나라도 문제면 전체 결과를 반환하지 않는다.
- AC-19: 모호한 `와`, `과` 표현에서 임의 축약으로 제목을 훼손하지 않으며, 실제 Gemini 전송 범위를 분석 전에 안내한다.
- AC-20: 소요 시간이 시작 시각으로 인식되지 않도록 하며, 여러 시작 후보와 변환 불가 시각을 구분해 안내한다. 기존 분석 보류와 추가 모델 호출 방지 경계를 유지한다.
- AC-21: 숫자 기반 `시간 후/전` 및 `분 후/전` 표현을 확인 대상으로 보류하고, 기준 시각을 잘못 확정하지 않으며 추가 모델 호출을 하지 않는다. 정상 시각과 단순 소요 시간 회귀를 유지한다.

## 미결정 사항

## 주요 설계 변경

이전 이력은 Git의 `cb37966` 명세와 연결된 기존 관찰 문서에 보존한다. specRevision 12에서 Gemini 개발용 직접 호출로 변경했고, 13에서 시간 범위의 시작 시각을 정리했으며, 14에서 밤 12시를 다음 날 00:00으로 정했다. specRevision 15는 현재 브랜치의 목표를 모델 설정 및 핵심 로직 검증으로 제한하고 기존 UI와 실제 저장 및 이미지 통합 완료 조건을 후속 범위로 이동했다. 16에서는 해석할 수 없는 시작 시각을 확인 대상으로 보류하고 제목 원문 보존을 보완했다. 17에서는 소요 시간의 오인식과 복수 시각 안내를 수정한다.

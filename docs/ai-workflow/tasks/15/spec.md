## 목적

실제 macOS 앱에서 Foundation Models, EventKit, Vision을 연결해 텍스트와 이미지 입력을 Apple 미리 알림에 등록할 수 있는지 확인한다. 디자인 완성이나 정량 벤치마크보다 대표 합성 입력의 전체 등록 경로를 먼저 검증한다. 착수 당시에는 메뉴바와 텍스트 입력 및 기본 테스트만 있었다. 1차 커밋에서 분석과 저장의 최소 경로를 구현했고, 현재는 2차 텍스트 추출 가드를 검증한다. 실제 권한과 저장 대조는 별도로 남아 있다.

## 작업 범위

### 포함

- 실제 Mac의 모델 사용 가능 여부 및 실행 환경 확인.
- 한국어 텍스트 한 건과 여러 건의 구조화 추출, 날짜 및 목록 검증.
- EventKit 권한과 기존 쓰기 가능 목록 조회, 사용자 확인 후 테스트 항목 저장.
- 기존 메뉴바 화면에 필요한 최소 분석, 결과 수정, 목록 선택 및 등록 UI 연결.
- 이미지 1장의 선택과 붙여넣기, OCR, 선택적 보조 설명을 공통 분석 경로에 연결.
- 순수 로직 자동 테스트와 실패 모의 실행, 실제 Mac 관찰 기록.
- 2차 텍스트 검증: 행동과 필드의 원문 근거, 일정별 시각 귀속, 공유 날짜와 누락 및 중복 의심 검사. 가드 위반일 때만 최대 한 번 재분석하며 1차 커밋과 같은 합성 입력으로 비교한다.

### 제외

- 웹, 디자인 시스템 완성, 전체 MVP 화면과 모든 UX 상태의 제품 수준 구현.
- 신규 서버, 클라우드 모델, 별도 모델 배포와 학습, 상세 품질 비교 및 성능 기준 신설.
- 배포, CI 정책 변경, 자동 중복 제거, 영구 초안 복원 및 부분 저장 복구 UX 확정.
- 기존 미리 알림 수정과 삭제, 테스트 준비를 위한 자동 목록 또는 항목 생성.

## 설계 결정

### 실행 순서

1. 환경과 모델: macOS 및 Xcode 버전, Apple Intelligence 활성 상태와 모델 가용성을 기록한다. 사용 불가이면 원인을 남기며 모의 응답을 실제 모델 성공으로 취급하지 않는다.
2. 텍스트 분석: 한 건부터 시작해 여러 건으로 넓힌다. 구조화 추출 결과를 검증한 뒤 편집 가능한 초안으로 넘긴다.
3. 미리 알림: 검증 화면의 명시적인 접근 동작으로 권한을 요청하고 기존 목록을 조회한다. 제품의 최종 권한 요청 시점은 별도 미정 사항이다. 선택한 테스트 대상에 최종값을 저장하고 Apple 미리 알림 앱에서 확인한다.
4. 이미지: Vision OCR로 읽은 텍스트와 선택적 보조 설명을 같은 분석 경로에 전달한다. 원본 이미지가 Foundation Models의 직접 입력이라고 가정하지 않는다.
5. 실패와 증거: 사용 불가, 거부, 빈 결과, 잘못된 출력 및 저장 실패를 구분하고 관찰 결과를 기록한다.

### 파일 구조와 책임

기존 `apps/macos/Ttak`의 App, Features, Models, Services, Resources 구조와 기존 테스트 타깃을 사용한다. 아래는 후속 구현 시 검토할 파일 배치안이며 새 아키텍처나 모든 타입에 대한 프로토콜을 강제하지 않는다.

| 경로 또는 타입 제안 | 책임 |
| --- | --- |
| `Features/ScheduleInput` | 입력과 첨부, 분석 실행, 초안 수정 및 명시적 등록 UI |
| `Models/ScheduleDraft.swift` | 안정적인 항목 ID, 제목, 날짜와 시각, 선택 목록, 부가 정보 및 확인 필요 상태 |
| `Services/ScheduleAnalyzer.swift` | 모델 가용성, 구조화 추출, 분석 문맥 전달 |
| `Services/ScheduleExtractionGuard.swift` | 행동 원문 위치, 일정별 날짜와 시각 귀속, 누락 및 중복 의심 검사와 재분석 행동의 근거 복원 |
| `Services/ReminderStore.swift` | 권한, 기존 목록 조회, 저장 직전 목록 재검증과 항목별 저장 결과 |
| `Services/ImageTextRecognizer.swift` | OCR 결과 또는 인식 실패 반환 |
| `apps/macos/TtakTests` | 날짜 및 출력 검증, 대체 저장 구현을 통한 실패 테스트 |

SwiftUI 상태와 외부 API 호출을 구분하고 테스트에 필요한 경계만 대체 가능하게 한다. API 세부 구현은 착수 시 공식 문서와 SDK에서 확인한다. 서명과 권한 설정은 실제 로컬 실행에 필요한 범위만 확인하며 배포 설정으로 확대하지 않는다.

### 상태와 데이터 흐름

`텍스트 또는 이미지 1장 → OCR이 필요한 경우 텍스트 추출 → 공통 일정 분석 → 출력 검증 → 초안 확인 및 수정 → 명시적 등록 → 저장 결과 확인`

- 상대 날짜는 분석 실행 시점에 고정한 사용자 로컬 날짜, 달력 및 시간대를 기준으로 계산한다. 모델이 만든 날짜 문자열을 그대로 저장하지 않는다.
- 명확하지 않은 시각을 임의로 채우지 않고 종료 정보와 원표현을 보존한다. 충돌하거나 무효한 날짜는 확인 대상으로 둔다.
- 실제 모델이 없는 시각을 만드는 사례가 발견되어, 시작 시각은 모델이 복사한 원문 표현을 실제 입력과 대조하고 Swift에서 정규화한다. 입력에 없는 시각, 모호한 표현과 종료 시각은 자동 확정하지 않고 원표현을 메모로 남긴다. 문맥별 추출 정확도를 보장하는 일반 자연어 파서나 전체 품질 벤치마크는 아니다.
- 이미지 OCR 자료와 사용자 보조 설명은 별도 값으로 전달한다. 보조 설명이 있는 경우 후보 추출 후 단순한 선택용 모델 호출을 한 번 더 수행하고, 후보 밖 인덱스는 오류로 처리한다. 선택 호출 실패를 전체 후보 반환으로 대체하지 않는다.
- 2차 가드 위반 때만 최대 한 번 행동 목록으로 단순화해 다시 추출한다. 같은 전체 입력에서 행동 원문 위치와 날짜 및 시각을 코드로 연결하고 다시 검증한다. 재분석이 여전히 유효하지 않으면 부분 성공 대신 분리 확인 오류와 입력을 유지한다. 미지원 날짜는 기존 날짜 확인 상태를 사용한다. 별도 부분 등록 UX를 추가하지 않는다.
- 쓰기 가능한 기존 목록 ID만 인정한다. 불확실한 추천은 미선택으로 남기고 기본 목록으로 대체하지 않는다.
- 분석, 수정, 제외와 취소는 저장과 분리한다. 저장은 사용자가 확인한 최종값으로만 실행한다.
- 분석과 등록의 반복 실행 및 오래된 응답으로 상태가 덮이는 경우를 검토한다. 세부 입력 변경 및 창 수명 UX는 이 검증으로 자동 확정하지 않는다.
- 오류를 전체 성공으로 표시하지 않는다. 부분 성공 또는 결과 불명은 대체 저장 구현으로 재현해 관찰하며 전체 자동 재등록을 추가하지 않는다.

## 완료 조건

- AC-1: 실제 기기의 실행 환경과 모델 가용성을 기록하고, 사용 가능한 환경에서 실제 모델 응답을 얻는다. 불가 환경만 관찰했다면 실제 모델 경로는 미검증으로 남긴다.
- AC-2: 대표 합성 한국어 텍스트 한 건과 여러 건을 편집 가능한 초안으로 추출한다. 날짜 기준, 모호한 시각 및 후보 밖 목록 ID 처리를 검증한다.
- AC-3: 실제 EventKit 권한과 목록 조회를 확인하고, 사용자가 선택한 테스트 대상에 수정한 최종값을 명시적으로 저장해 Apple 미리 알림 앱에서 대조한다. 분석과 취소만으로는 저장하지 않는다.
- AC-4: 합성 이미지의 파일 선택과 붙여넣기, 이미지 단독 및 보조 설명 경로를 확인하고 공통 초안 및 실제 등록 경로에 연결한다.
- AC-5: 주요 오류를 구분하며 잘못된 출력으로 저장하거나 저장 실패를 전체 성공으로 처리하지 않는다. 부분 성공과 결과 불명은 대체 저장 구현으로 확인하고 복구의 미정 사항을 기록한다.
- AC-6: 변경한 Swift 코드의 포맷, 빌드와 테스트를 실행하고 실제 기기 관찰 결과, 기대값과 실제값, 제약 및 후속 결정을 남긴다. 미실행 검증을 통과로 표시하지 않는다.
- AC-7: 원문에 없는 행동과 다른 일정의 시각, 중복 및 누락 의심과 재분석 상한을 코드 테스트로 검증한다. 1차 커밋과 2차 실제 모델에 같은 합성 사례를 실행해 누락, 과다 추출, 날짜 및 시각과 선택 오류 및 보류 결과를 구분해 기록한다. 모든 결과를 보류한 것을 정확도 개선으로 보고하지 않는다.

이미지의 메시지 시각, 종료 시각만 있는 표현 및 충돌 연도도 관찰 사례로 사용한다. 이 소규모 예제 결과를 전체 한국어 정확도나 OCR 품질 보장으로 일반화하지 않는다. 개인 일정 원문과 개인 캡처는 공유 로그나 Git에 남기지 않는다.

## 미결정 사항

- 실제 저장을 확인할 테스트 목록은 실행 시 사용자가 선택한다. 선택 전에는 실제 쓰기를 실행하지 않는다.
- 최종 권한 요청 시점, 입력 변경 후 결과 보존, 미선택 목록 및 무효 날짜의 일괄 등록 안내, 부분 성공 복구는 제품 UX 결정이 필요하다. 단일 항목의 명시적 확인 경로와 모의 실패 검증을 먼저 진행할 수 있다.
- 이미지 형식과 크기 제한, 창 닫기 및 재실행 보존, 실제 알림 발생 정책은 이번 기술 검증으로 임의 확정하지 않는다. 연결을 막는 제약이 발견되면 근거와 선택안을 기록한다.
- 모델 품질이나 OCR 제약이 대표 경로를 막으면 실패 사례와 영향 범위를 보고하고 프롬프트 또는 입력 처리 개선안을 검토한다. 임의의 클라우드 우회를 추가하지 않는다.

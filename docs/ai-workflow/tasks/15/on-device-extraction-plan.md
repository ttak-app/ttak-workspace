# 온디바이스 일정 추출 개선 계획

## 목적과 현재 근거

사용자가 온디바이스 모델을 우선 사용하고 일정별 시각과 인물 및 행동 추출을 개선할 계획을 요청했다. 최초 작성은 설계 기록이었으며, 이후 사용자가 서브 에이전트 구현을 승인했다. 현재 구현 선택과 실행 결과는 [개선 결과](on-device-extraction-results.md)를 따른다. 아래 비교 순서는 최초 계획의 기록이다.

이전 실제 모델은 여러 일정과 숫자 시각을 추출했으나 제목에 문장 표현과 어색한 공백이 남았다. `98d779d`에서는 장소와 제목 조각의 검증 실패로 전체 분석이 중단됐다. 검증 전 응답을 기록하지 않아 모델의 잘못된 값과 가드의 과도한 거부를 구분하지 못한다. 모델 자체의 한국어 추출 한계로 단정하지 않는다.

## 진행 순서

1. 검증 실행 도구에 최초 구조화 응답, 재분석 응답, 필드별 가드 판정과 소요 시간을 관찰할 경로를 만든다. 현재 동작을 바꾸기 전에 실패 사례를 저장 없이 재현한다. 개인 입력과 원시 응답은 Git에서 제외한 로컬 검증 증거에만 두고 일반 앱 로그에는 남기지 않는다.
2. 같은 모델과 입력으로 현재 계약과 축소 계약을 비교한다. 축소안은 일정별 연속 원문 구간, 행동 구절, 날짜 표현과 시작 시각 표현을 중심으로 한다. 현재의 필수 제목 조각 생성, 별도 장소 분리와 자동 목록 추천을 비교 경로에서 제외하고 선택 목록은 사용자가 정한다. 원문에 있는 장소와 진행 방식 등의 정보는 행동 구절 또는 원문에 보존한다.
3. 축소안에 선택적인 인물 표현과 행동 핵심 구절을 더한 비교안을 만든다. 각 값은 같은 일정 원문에서 복사하며, 부재나 불확실성을 허용한다. `동아리` 같은 집단 표현을 사람 이름이나 추측한 구성원으로 바꾸지 않는다. 분류 필드가 정확도나 처리 시간을 악화시키면 축소안을 유지할 수 있다. 실제 결과를 보기 전에 최종 스키마를 확정하지 않는다.
4. 검증된 표현으로 Swift가 날짜 계산과 시각 변환 및 제한된 제목 정리를 수행한다. 고유명사, 부정, 취소, 대상과 진행 방식을 보존한다. 불확실한 정리는 행동 원문을 유지하고 원문을 메모에 남긴다. 사람 이름 사전이나 조사 전체 삭제로 해결하지 않는다.
5. 텍스트 전후 비교 후 Vision OCR 텍스트에도 같은 경로를 적용한다. OCR 원문과 정답 전사문을 각각 분석해 OCR 오류와 일정 분석 오류를 구분한다. 분석 결과가 안정된 다음 사용자가 확인한 값으로 실제 저장을 대조한다.

일정 경계 파악과 필드 추출은 논리적인 작업 순서다. 기본 비교안은 입력 한 건의 전체 일정을 한 번의 구조화 모델 호출로 추출하며, 키워드나 일정마다 별도 호출하는 구조를 도입하지 않는다. 기존 재분석 최대 한 번의 상한을 늘리지 않는다. 사용자 보조 설명에 따른 기존 후보 선택 호출은 별도 경로로 유지하고 기본 추출 호출 수와 구분한다.

## 기대 출력 예시

아래는 합성 입력의 목표 예시이며 실제 모델 결과가 아니다.

| 일정 원문 | 시각 원문 | 인물 또는 집단 원문 | 행동 핵심 예시 | 제목 목표 예시 |
| --- | --- | --- | --- | --- |
| 9시에 산책갈거야 | 9시 | 없음 | 산책 | 산책 |
| 12시에 민수랑 점심 약속 있어 역 앞에서 | 12시 | 민수 | 점심 약속 | 민수 점심 약속 |
| 18시에 독서모임 회식있어 | 18시 | 독서모임 | 회식 | 독서모임 회식 |

인물 또는 집단은 비교를 위한 보조 근거다. 위 열을 모두 필수 모델 필드로 추가한다는 의미가 아니다. 장소를 제목에서 생략하려면 같은 일정의 메모에 보존해야 하며, 별도 분리가 불확실하면 행동 원문과 장소 표현을 함께 유지한다. 숫자 시각의 최종 24시간제 변환은 Swift가 담당한다.

## 가드와 저장 경계

- 필수 근거: 일정 구간과 행동의 원문 존재, 필드의 일정별 귀속, 유효한 날짜와 시각, 중복과 누락 의심. 원문에 없는 행동이나 다른 일정의 시각을 정상 결과로 넘기지 않는다.
- 선택적인 제목 가공과 장소 분리 실패: 원문 행동을 유지해 의미 정보가 보존되는 경우에 한해 표시 정리를 생략하는 대안을 비교한다. 선택 필드 오류를 조용히 성공으로 숨기지 않고 검증 기록에 구분한다.
- 애매한 날짜와 시각: 계산하거나 확정하지 않고 기존 확인 경로를 사용한다. 누락과 잘못된 귀속이 해결되지 않으면 기존 전체 보류 동작을 유지한다. 새로운 부분 저장 UX를 확정하지 않는다.
- 모델 초안과 자동 후처리값은 각각 관찰한다. 사람이 고친 결과를 모델의 성공으로 집계하지 않는다. 분석 및 비교 중 EventKit 쓰기는 호출하지 않는다.

## 검증과 채택 기준

고정한 합성 사례에 단일 및 복수 일정, 공유 날짜, 일정마다 다른 인물과 시각, 반복 행동, 붙여 쓴 표현, 고유명사, 온라인 도구, 장소, 부정과 취소 및 일정이 아닌 문장을 포함한다. 각 입력의 기대 일정과 근거를 실행 전에 작성한다.

| 평가 대상 | 확인할 내용 |
| --- | --- |
| 일정 분리 | 기대 개수, 누락, 과다 추출과 중복 |
| 원시 필드 | 인물과 행동 및 수식어 보존, 날짜와 시각의 올바른 귀속 |
| 후처리 | 제목의 가독성, 원문 의미 보존과 장소 메모 보존 |
| 가드 | 실제 잘못된 출력 차단과 유효한 출력의 거부를 구분 |
| 실행 비용 | 모델 호출 수, 각 단계 및 전체 소요 시간 |
| 반복성 | 같은 입력 반복 시 차이, 모델과 OS 및 소스 버전 기록 |

단어의 존재만으로 성공 판정하지 않고 올바른 일정에 연결됐는지 함께 본다. 알려진 잘못된 행동과 시각을 새로 통과시키지 않으면서 정상 초안 반환과 의미 보존이 개선됐는지 평가한다. 모든 결과를 보류한 것을 정확도 개선으로 집계하지 않는다. 합성 코드 테스트와 실제 모델 결과를 별도로 보고한다.

## 변경 대상과 순서

1. 로컬 검증 실행 도구: 응답과 검증 결과 관찰부터 추가.
2. `ScheduleAnalyzer.swift`: 비교용 추출 계약과 프롬프트 축소. 최종안은 실제 비교 후 선정.
3. `ScheduleExtractionGuard.swift`, `ScheduleTitleNormalizer.swift`: 선정된 계약의 원문 대조와 보수적 제목 처리.
4. `TtakTests`: 의미 누락, 인물과 시각의 잘못된 연결, 선택 필드 오류와 정상 반환 경계를 검증.
5. 기존 이미지 입력과 초안 확인 및 저장 경로: 회귀 확인. 새 서버, API 연결, UI 전면 수정과 새 라이브러리는 포함하지 않는다.

최초 구현 단위는 관찰 기능이었다. 실제 비교에서 여러 필드의 날짜와 시각 혼동 및 인물 혼입을 확인해, 모델은 일정 원문 구간만 추출하고 Swift가 날짜와 시각을 처리하는 안으로 좁혔다. 미채택 실험 분기는 앱 코드에서 제거하고 실행 증거에 보존한다. 미리 알림 저장은 이번 개선 비교에서 실행하지 않는다.

## 변경한 처리

`모델의 행동별 원문 추출 → Swift 원문 위치 및 귀속 검증 → 위반 시 행동 목록으로 한 번 재분석 → 코드가 원문 구간과 날짜 및 시각 복원 → 재검증 → 초안`

- 행동과 원문 구간의 실제 위치, 일정별 시각, 같은 문장 안의 공유 날짜, 반복된 제목의 다른 발생 위치를 확인한다. 모호한 중복 위치를 임의로 첫 위치에 붙이지 않는다.
- `하고`, 줄바꿈과 날짜 및 시각은 분리 단서다. 연결어 개수로 일정 수를 결정하거나 고정 행동 사전으로 일정을 추가하지 않는다.
- 최초 6필드 추출이 틀린 경우 같은 복잡한 추출을 반복하지 않고 행동 이름만 다시 추출한다. 행동 원문을 복원하는 과정에서 모델이 추가한 `하기` 및 `가기`를 원문 기저와 대조할 수 있으며, 동의어를 임의 생성하지 않는다.
- 재분석은 위반이 관찰된 때만 한 번 수행한다. 재분석이 계속 유효하지 않으면 부분 성공 대신 분리 확인 오류를 반환한다. 보조 설명이 있으면 기존 선택 호출이 별도로 한 번 추가될 수 있다.
- 미지원 날짜는 오늘로 추측하지 않고 기존 날짜 확인 상태로 둔다. 날짜가 실제로 생략된 경우의 오늘 기본값은 유지한다. 모든 미지원 자연어 날짜를 탐지하는 파서는 아니다.

## 같은 합성 입력 12개 비교

평가 기준은 항목 수, 원문 행동을 나타내는 미리 지정한 제목 부분 문자열, 날짜, 시작 시각 및 날짜 확인 상태의 일치다. 제목 전체 문구, 인물 및 장소 보존, 메모 완전성과 목록 추천은 이 점수에 포함하지 않았다. 아래 일치는 이 제한된 기준을 뜻하며 일반 정확도 점수가 아니다.

| 입력 또는 조건 | 1차 | 2차 |
| --- | --- | --- |
| 내일 오전 9시 회의 | 일치 | 일치 |
| 내일 오전 9시 런닝하고 저녁에 회식 | 회식 누락 | 2건, 내일 공유, 런닝만 09:00 |
| 내일 런닝하고 모레 정훈 점심 | 일치 | 일치 |

| 내일 회의하고 모레 회의 | 둘 다 내일로 반환 | 각각 내일과 모레 |
| 2026년 11월 10일 오후 2시 팀 미팅 | 일치 | 일치 |
| 장소: 가상 회의실 / 준비물: 노트북 | 부가 정보를 일정으로 반환 | 일정 없음 |
| 오후 3시 병원 예약 | 일치 | 일치 |
| 내일신문 구독 | 내일로 잘못 해석 | 날짜 미지정 기준일 유지 |

| 내일 오전 10시 도서관 가고 오후 2시 치과 예약 | 일치 | 2건, 10:00과 14:00 |

1차의 누락 1사례, 과다 추출 1사례, 날짜 오류 2사례가 이 실행에서는 개선됐다. 모든 결과를 보류해서 얻은 점수는 아니다. 위 12개는 개선 과정에서 결과를 확인한 회귀 집합이다. 내부 ID `heldout`인 도서관과 치과 사례도 개선 과정에서 확인했으므로 독립 평가로 취급하지 않는다.

동일 12개 단일 실행의 평균 관찰 시간은 1차 3.07초, 2차 3.58초였다. 기기 상태와 재분석 여부가 섞인 관찰이며 성능 기준이나 일반적인 지연 시간으로 해석하지 않는다. 실제 모델 호출 횟수별 성능 측정은 하지 않았다.

## 추가 표현 5개

회귀 집합을 개선한 뒤 기대값을 정해 실행했으며 아래 결과에 맞춰 추가 프롬프트를 조정하지 않았다. 이후 리뷰에서 찾은 문법 및 메타데이터 결함을 수정한 최종 소스로 같은 5개를 다시 실행했고 결과는 같았다.

| 새로운 입력 | 최종 관찰 | 판정 |
| --- | --- | --- |
| 오늘 오후 4시 기획안 검토하고 내일 오전 11시 고객 통화 | 오늘 16:00 / 내일 11:00, 2건 | 지정 기준 일치 |
| 모레 오전 8시 산책하고 오후 6시 친구와 저녁 식사 | 모레 08:00 / 18:00, 2건 | 지정 기준 일치. 두 번째 제목은 `저녁 식사`로 줄어 `친구와`가 제목에서 빠짐 |
| 제품 및 운영 회의 | 복합 제목 1건 | 지정 기준 일치 |
| 다음 주 월요일 오전 10시 면담 | 날짜 비움, 확인 필요, 10:00 | 계획한 미지원 날짜 보류. 1차는 잘못된 날짜로 확정 |
| 내일 회의 말고 모레 점심만 등록해줘 | 점심만 1건, 날짜 비움 및 확인 필요 | 선택 대상은 개선됐으나 날짜 자동 확정 실패. 1차는 회의까지 반환 |

정상적으로 날짜까지 확정한 3개, 계획한 미지원 날짜 확인 1개, 불필요한 날짜 확인이 남은 1개로 구분한다. 마지막 사례는 입력의 내일과 모레가 같은 근거 구간에 남아 가드가 확인을 요구한 것이다. 점심의 모레를 확정하는 일반적인 제외 문맥 처리는 남아 있다. 5개 모두 정상 성공했다고 보고하지 않는다.

제목 부분 문자열 기준만으로는 `친구와` 같은 인물 조건 손실을 잡지 못한다. 각 행동 구간은 메모의 `원문:`으로 보존되지만 모든 정보가 원하는 필드에 구조화됐다는 뜻은 아니다.

## 자동 검증과 리뷰

- Swift Testing: 최종 60개 테스트, 5개 스위트 통과. 기존 27개에서 가드 및 재분석 테스트를 추가했다. 매개변수 테스트는 같은 테스트의 여러 입력으로 실행된다.
- 원문에 없는 행동, 다른 일정의 시각, 잘못된 날짜 참조, 반복 원문의 모호함, 전체 입력 인용으로 누락을 숨기는 경우, 중복 및 다른 일정 메모를 검사했다.
- 최초 정상 결과는 재분석하지 않고, 위반 때 한 번만 재분석하며, 반복 위반과 빈 재분석을 정상 성공으로 숨기지 않는지 대체 모델로 확인했다.
- 읽기 전용 서브 에이전트 리뷰에서 상대 날짜 조사 누락, `9시 반`의 30분 유실, `메시지 발송`의 과잉 메타정보 제외를 발견했다. 수정과 회귀 테스트를 추가했고 에이전트가 코드상 해결을 재확인했다.
- 부모 검토에서 줄바꿈을 넘어선 행동 문자열 결합과 `문서 작성하고 내일 회의`의 날짜 누락도 수정했다.
- 실제 모델 실험 중 최초 필드 추출의 과도한 원문 인용과 행동 합침, 복합 회의 제목의 과다 분리가 있었다. 단순 행동 재분석과 복합 제목 지침을 보완한 최종 결과를 위에 기록했다. 중간 실패 로그를 최종 통과로 덮어쓰지 않았다.

## 완료 범위와 남은 확인

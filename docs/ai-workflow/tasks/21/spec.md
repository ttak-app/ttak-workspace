# 작업 명세: 공통 입력 및 이미지 첨부 구현

## 연결 정보

- 이슈: #21 / https://github.com/ttak-app/ttak-workspace/issues/21
- 브랜치: feat/schedule-composer/#21
- specRevision: 4

## 목적

일정 텍스트와 선택적 이미지 한 장을 같은 영역에서 입력하고, 분석 요청을 외부에 전달하는 재사용 가능한 macOS 입력 UI를 준비한다.

## 작업 범위

### 포함

- 공통 입력 View, 파일 선택과 이미지 붙여넣기, 미리보기와 삭제, 분석 버튼과 진행 표시.
- 실제 View를 사용하는 독립적인 Debug 갤러리 샘플과 수동 확인 방법.
- 파일 선택 취소와 첨부 삭제 시 기존 텍스트 보존, 유효한 입력이 없는 분석 차단.

### 제외

- OCR, 모델 분석, 미리 알림 저장 호출, 결과 패널, 전체 앱 흐름 연결 및 기존 기술 검증 화면 전체 교체.
- 랜딩 전용 요소, 새 디자인 시스템과 미합의 이미지 제한 정책.

## 설계 결정

- 사용자와 공유한 입력 영역 구조를 기준으로 구현한다. PNG, JPEG, HEIC, TIFF를 지원하고 별도 크기와 해상도 제한은 이번에 추가하지 않는다. 두 번째 이미지는 읽기와 검증에 성공한 경우 기존 첨부를 교체한다. Enter는 줄바꿈, ⌘Enter는 분석 요청이다.
- 사용자 제공 참고 이미지와 로컬 랜딩의 입력 바를 시각적 기준으로 삼는다. 기본은 한 줄 높이의 긴 둥근 입력 바이며 왼쪽 +, 중앙 텍스트, 오른쪽 원형 화살표를 한 행에 배치한다. Apple Liquid Glass의 regular 재질에 기존 브랜드 토큰의 옅은 틴트를 더해 뿌연 유리 느낌을 표현한다. 여러 줄은 최대 네 줄까지 높이가 늘고 이후 스크롤한다.
- `ScheduleComposer`가 입력 영역, 이미지 선택, 미리보기와 분석 버튼을 조합한다. 미리보기는 입력창 아래에 놓는다. 별도 버튼 타입은 재사용 필요성이 확인될 때만 추출한다.
- 부모가 텍스트와 첨부의 단일 소유자다. 텍스트와 첨부는 바인딩 또는 변경 액션으로 전달하고, 분석 가능 여부와 진행 및 비활성 상태는 외부에서 전달한다. 분석 요청은 클로저로 알린다. 첨부 값은 이미지 데이터와 표시 이름을 함께 갖는 값 타입을 제안한다.
- 실행은 외부에서 허용하고 진행 중이 아니며, 공백과 줄바꿈을 제외한 텍스트 또는 유효한 첨부가 있을 때만 가능하다. 버튼의 비활성과 액션 진입 모두에서 확인해 중복 요청을 막는다.
- 파일 선택은 기존 `NSOpenPanel`과 보안 범위 접근 해제 패턴을 참고한다. 클립보드 이미지 처리도 기존 화면을 참고하되 일반 텍스트의 붙여넣기를 가로채지 않도록 실제 포커스에서 검증한다. 파일 읽기와 이미지 해석 실패는 안내하고 기존 입력을 유지한다.
- 파일 선택 취소는 상태를 바꾸지 않는다. 삭제는 첨부만 제거한다. 오류 표시는 입력 컴포넌트 내부의 일시적인 상태로 제안하며 다른 상태 안내 컴포넌트에 의존하지 않는다.
- 샘플은 별도 Debug View에 로컬 상태와 모의 액션을 두고 공통 갤러리에는 등록만 추가한다. 기존 `ScheduleInputModel`과 서비스는 생성하지 않는다. 새 Swift 파일은 Xcode 프로젝트의 파일 참조와 Sources에 연결한다.
- 기존 `ScheduleInputView`와 `ScheduleInputModel`의 파일 선택, 붙여넣기와 입력 유효성 코드는 참고 대상이다. 기존 화면에 실제 분석 연결을 강제하지 않으며, 결과 무효화 정책도 이 작업에서 확정하지 않는다.

## 완료 조건

- AC-1: 하나의 입력 영역에서 텍스트 단독, 이미지 단독, 이미지와 설명을 작성하고 동일한 분석 액션을 요청한다. 공백뿐인 텍스트와 이미지가 모두 없으면 요청할 수 없다.
- AC-2: 파일 선택과 이미지 붙여넣기로 이미지 한 장을 첨부하고, 첨부가 있을 때만 미리보기와 삭제를 표시한다.
- AC-3: 파일 선택 취소와 읽기 실패 시 기존 입력을 유지하며, 이미지 삭제 시 텍스트를 유지한다.
- AC-4: 외부에서 전달한 진행 및 비활성 상태를 표현하고 분석 중 중복 요청을 막는다.
- AC-5: 갤러리에서 실제 컴포넌트의 입력 조합과 진행 및 비활성 상태를 조작할 수 있으며 분석 액션은 모의 동작만 수행한다.
- AC-6: 기존 토큰과 네이티브 입력 및 버튼을 사용하고 갤러리 확인 방법을 문서화한다. 참고 이미지의 한 행 배치, 둥근 형태, 입력 바 아래 첨부 배치와 유리 재질을 실제 화면에서 대조한다.

## 검증 방법

| 완료 조건 | 확인 방법 | 기대 결과 |
|---|---|---|
| AC-1, AC-4 | 입력 유효성 및 요청 차단 테스트와 갤러리 조작 | 세 입력 조합에서만 허용되고 진행 및 비활성 중 요청되지 않음 |
| AC-2, AC-3 | 실제 Mac에서 파일 선택, 취소, 실패, 이미지 및 텍스트 붙여넣기와 삭제 | 미리보기와 보존 동작이 맞고 일반 텍스트 붙여넣기가 동작함 |
| AC-5, AC-6 | Debug 갤러리 및 밝은/어두운 외관 확인 | 실제 View의 상태가 표시되고 외부 서비스 호출이 없음 |
| 전체 | `npm run format:macos`, `npm run format:check:macos`, `npm run macos:build`, `npm run macos:test`, `npm run workflow:harness-check` | 포맷과 빌드, 영향받는 기존 테스트 및 하네스 검사 통과. 실제 조작 결과는 별도 기록 |

## 미결정 사항

- 이번 입력 정책은 사용자 승인 완료. 이미지 크기와 해상도의 수치 제한이 필요해지면 후속 논의한다.
- 전체 흐름 연결 전 결정: 분석 중 입력 수정과 취소, 결과 표시 후 입력 변경 시 결과 무효화. 이 작업의 진행 상태 표현과 중복 요청 차단은 별도다.
- PR #20의 develop 병합을 확인하고 최신 origin/develop에서 작업 브랜치를 생성했다.

# 작업 명세: 입력 및 일정 결과 확인 화면 상태 연결

## 연결 정보

- 이슈: #29 / https://github.com/ttak-app/ttak-workspace/issues/29
- 브랜치: feat/schedule-flow/#29
- specRevision: 2
- 선행 작업: #27 ScheduleResultPanel, #23 ScheduleStatusView

## 목적

기존 입력 컴포넌트, 진행과 오류 안내, 일정 결과 편집 컴포넌트를 실제 앱 화면의 단일 흐름으로 연결한다. 이 작업은 화면 상태와 컴포넌트 전이를 담당하며 OCR과 AI 분석 및 EventKit 접근/저장은 후속 이슈에서 연결한다.

## 작업 범위

### 포함

- 입력, 분석 진행, 결과 확인, 취소, 실패 및 완료 상태를 소유하는 최소 상태 모델을 구성한다.
- 입력 컴포넌트의 분석 요청과 결과 패널의 취소와 등록 콜백을 앱 흐름에 연결한다.
- 기존 분석과 저장 구현 대신 명시적인 주입 경계 또는 임시 샘플 응답을 사용해 컴포넌트 전이를 연결한다.
- 분석 진행 중 중복 요청을 막고, 사용자의 취소 또는 모델 해제 시 진행 task를 안전하게 취소한다. 모델은 화면보다 오래 사는 소유자가 관리하며, 패널을 닫아도 분석은 계속된다.
- 결과 취소 시 입력과 이미지 첨부를 보존하고, 다음 입력 복귀 흐름을 제공한다.
- 등록 콜백은 실제 저장 없이 후속 저장 연결 지점으로 전달한다.

### 제외

- OCR 및 AI 모델 호출
- 미리 알림 권한 요청 및 목록 조회
- EventKit 저장과 부분 성공 처리
- 제품 UX에서 정하지 않은 재시도와 권한 정책 추가

## 완료 조건

- AC-1: 기본 입력에서 분석 요청, 진행, 결과 확인으로 전이가 이어진다.
- AC-2: 결과 취소 시 원래 텍스트와 첨부 이미지가 보존된다.
- AC-3: 진행 중 중복 분석은 실행되지 않으며, 취소하거나 모델이 해제된 이전 작업은 이후 상태를 덮어쓰지 않는다. 패널을 닫았다 다시 열어도 입력, 진행 중인 분석, 결과가 유지된다.
- AC-4: 빈 결과와 분석 오류가 기존 상태 안내 컴포넌트로 표현되고 등록은 진행되지 않는다.
- AC-5: 등록 액션은 편집된 유효 초안만 후속 저장 경계로 전달하며 이 이슈에서 EventKit 쓰기는 하지 않는다.
- AC-6: 상태 전이와 입력 보존을 합성 데이터 기반 테스트로 검증한다.

## 검증 방법

- Swift 포맷, macOS 빌드, 관련 테스트 및 기존 검증 실행
- 앱에서 입력 → 분석 진행 → 결과 편집 → 취소/등록 콜백 흐름 확인

## 변경 기록

- specRevision 2: 메뉴바 패널을 닫으면 입력과 결과가 사라지는 문제를 확인했다. 사용자와 합의해 모델을 패널보다 오래 사는 소유자(앱 delegate)가 관리하고, 분석 중 패널을 닫아도 분석을 계속하도록 바꿨다. 화면 종료 시 분석을 취소하던 처리는 제거했다.
- 검증 영향: AC-3의 비동기 무효화는 `ScheduleFlowModelTests`로 계속 검증한다. 패널 재오픈 시 상태 유지는 모델 소유권이 뷰 계층에 있어 단위 테스트로 검증하지 못하므로 실제 메뉴바 조작으로 확인하고 결과를 기록한다.
- 결과 화면 합의: 일정 카드 목록은 앞의 3개 카드 높이까지만 보이고 그 이상은 목록 안에서 스크롤한다. 메모는 3줄 높이를 넘으면 안에서 스크롤한다. 제목과 취소 및 등록 버튼은 고정한다.
- 등록 피드백 합의: 이 이슈에서는 등록 버튼을 눌러도 화면 변화를 추가하지 않는다. 저장 결과 표시는 실제 저장을 연결하는 후속 이슈에서 다룬다.
- 개발용 샘플: 입력 줄 수만큼 일정을 만들고, 입력에 `빈결과` 또는 `오류`가 있으면 해당 상태를 보여준다. DEBUG 전용이다.
- UI 조정 합의: 상태 안내 카드 배경을 글래스 효과로 바꾸고 tint 불투명도는 0.5로 한다. 뒤 화면이 비쳐 가독성이 떨어지는 문제를 줄이기 위한 조정이다.

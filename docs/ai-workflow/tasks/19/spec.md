# 작업 명세: 개발용 컴포넌트 갤러리 구성

## 연결 정보

- 이슈: #19 / https://github.com/ttak-app/ttak-workspace/issues/19
- 브랜치: feat/component-gallery/#19
- specRevision: 2

## 목적

사용자가 실제 SwiftUI 구성 요소와 상태 샘플을 앱에서 직접 확인할 수 있게 한다. 선행 PR #18은 develop에 병합됐다.

## 작업 범위

### 포함

- Debug 전용 갤러리 창과 메뉴바 입력 화면의 개발용 진입점
- 샘플 선택과 기본, 비활성, 진행, 오류 상태 전환
- 기존 브랜드 색상과 네이티브 글자 및 컨트롤 사용 예시
- 실제 앱 View의 재사용을 보여주는 부작용 없는 공통 표시 요소
- 실행 방법과 후속 샘플 추가 안내

### 제외

- 새 디자인 시스템, 신규 입력 및 결과 편집 기능, 웹 화면
- OCR, 모델 요청, 권한 요청, 미리 알림 저장
- 배포 설정 변경과 후속 제품 UX 확정

## 설계 결정

- TtakApp에 #if DEBUG로 보호한 별도 Window를 추가한다. Debug 실행 시 갤러리를 먼저 표시하고 전면 활성화한다. 입력 화면의 개발용 버튼에서도 openWindow로 연다. Release에는 진입점과 갤러리 타입을 포함하지 않는다.
- Features/ComponentGallery에 샘플 목록과 순수 로컬 상태를 소유하는 View를 둔다. 서비스나 ScheduleInputModel을 갤러리에서 생성하지 않는다.
- 브랜드 색은 TtakTokens를 재사용한다. 글자와 컨트롤, 간격은 기존 네이티브 기준의 사용 예시로 표시하고 별도 공통 버튼 체계를 추가하지 않는다.
- 기존 앱의 부작용 없는 표시 요소를 최소 범위로 추출해 실제 화면과 갤러리가 같은 View를 사용하도록 한다. 새 제품 동작을 추가하지 않는다.
- 초기 샘플은 브랜드 색, 네이티브 타이포그래피와 간격, 컨트롤 상태, 공통 표시 요소다. 후속 입력과 결과 컴포넌트는 이번에 구현하지 않는다.
- 샘플 클릭은 로컬 상태만 바꾸며 진행 및 오류는 모의 상태임을 표시한다.

## 완료 조건

- AC-1: Debug 앱의 문서화된 진입점으로 갤러리를 열고 재진입할 수 있다.
- AC-2: 기존 토큰과 네이티브 스타일의 샘플을 선택하고 해당 상태 차이를 확인할 수 있다.
- AC-3: 실제 앱과 갤러리가 부작용 없는 동일 SwiftUI 표시 요소를 재사용한다.
- AC-4: 갤러리 진입 및 샘플 조작은 모델, OCR, 권한 요청과 저장 서비스를 호출하지 않는다.
- AC-5: Release 빌드에서 갤러리 진입점과 전용 구현이 제외된다.
- AC-6: 실행 경로, 확인 동작과 후속 샘플 추가 방법을 문서화한다.

## 검증 방법

| 완료 조건 | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| AC-1, AC-2 | Debug 빌드와 실제 앱 조작 | 창 열기와 샘플 상태 전환 확인 |
| AC-3, AC-4 | 코드 검토와 샘플 조작 | 동일 View 재사용, 서비스 호출 경로 없음 |
| AC-5 | Release 빌드와 조건부 코드 및 산출물 확인 | 개발 전용 구현 제외 |
| AC-6 | 문서와 구현 경로 대조 | 실행과 확장 절차 일치 |

Swift 포맷 검사, macos:build, 기존 macos:test, workflow:harness-check를 수행한다. 실제 앱 조작을 수행하지 못하면 해당 완료 조건은 미검증으로 보고한다.

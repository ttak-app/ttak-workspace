# Codex 하네스 사용 안내

스킬 이름을 매번 입력하지 않아도 AGENTS.md의 라우팅을 통해 필요한 문서를 읽는다.
새로운 Codex 대화에서는 저장소 폴더를 열고 해당 이슈를 알려준다.

| 요청 예시 | 결과 |
| --- | --- |
| “이 내용만 이슈로 올려줘” | 중복·템플릿·라벨을 확인하고 요청한 이슈만 생성 |
| “#번호 작업 브랜치 만들어줘” | develop 기준으로 합의된 이름의 브랜치 생성 |
| “#번호 구현 전에 설계하자” | 관련 코드·기획을 읽고 합의한 spec.md 작성 |
| “합의한 범위로 구현해줘” | 범위 안의 변경과 명세 갱신 |
| “검증하고 리뷰해줘” | 실제 실행·실패·한계와 변경 리뷰를 기록 |
| “#번호 작업 이어서 해줘” | resume과 명세로 이전 기록·오래된 증적 확인 |
| “PR 올려줘” | 준비 검사와 실제 게시 권한 확인 후 PR 게시 |

현재 작업 브랜치는 `chore/agent-harness-setting/#4`다.
설정 중에는 파일과 검증 결과를 검토하고, 커밋·push·PR은 사용자가 요청할 때 진행한다.

macOS 빌드: `npm run macos:build`. Xcode가 없으면 설치 필요 메시지와 실패 상태가 나온다.
웹 검사를 실행해 macOS 검증을 대체하지 않는다.
하네스 자체 검사는 `npm run workflow:harness-check`, `npm run workflow:test`다.
모든 명령·로컬 기록 형식과 한계는 [작업 기록](README.md)을 참고한다.

코드 작업에서는 [공통 컨벤션](../rules/coding-convention.md)을 통해 대상 언어의 규칙을 읽습니다.
브랜치·커밋·PR 작성은 [Git 컨벤션](../rules/git-convention.md)을 기준으로 합니다.
규칙을 별도로 매번 붙여넣지 않아도 에이전트 진입점과 스킬에서 연결된 문서를 읽도록 구성했습니다.

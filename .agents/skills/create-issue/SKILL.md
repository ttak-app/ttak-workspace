# GitHub 이슈 생성

[작업 흐름](../../../docs/rules/ai-workflow.md)을 따른다.
저장소·gh 인증·중복 이슈와 사용자가 요청한 개수/범위를 확인한다.
이미 대화에서 정해진 제목·내용을 다시 인터뷰하지 않는다.
[이슈 템플릿](../../../.github/ISSUE_TEMPLATE/issue_template.md)과 실제 저장소 라벨을 사용한다.
이름·색이 다른 중복 라벨이나 사용자가 요청하지 않은 추가 이슈를 만들지 않는다.
제목·본문을 파일로 준비하고 생성 권한이 있으면 `gh issue create --body-file`로 게시한다.
제목·설계가 미정이면 그 결정만 확인한다. 이슈 생성으로 브랜치·구현·push까지 진행하지 않는다.
생성한 실제 URL과 범위만 보고한다.

## Git 기준

[Git 컨벤션](../../../docs/rules/git-convention.md)의 제목·이슈 연결·라벨 규칙을 적용한다.
이미 사용자가 지정한 제목과 범위를 의미 없이 바꾸지 않는다.
